# P-010 과실 기반 부정

- 위험 구분: **부정(고의)** — 일부러 규정·통제를 어기거나 숨긴 행위다. 예외 조건에 고의성 신호를 넣는다(`wiki/patterns/index.md` 2절).
- 설명: 능동적 조작이 아닌 필요한 검증, 검증 또는 후속 의무를 수행하지 않아 부정 발생 — 종종 다른 부정 패턴을 가능하게 하거나 은폐. 클레임 지불 전 프로모션 이벤트가 실제로 발생했는지 확인하지 않고, 여러 프로모션에 걸쳐 누적 인센티브 수량을 확인하지 않으며, 벤더 검증 프로세스의 위험 신호를 무시하고 대리인이 계약 수량을 초과하는 것을 감지 없이 허용하며, 알려진 이상 사항을 준수 또는 감사 팀에 보고하지 않고 지급 실패 또는 계좌 불일치 후속 조치를 안 함
- ACFE: Negligence (Failure to Verify, Oversight)
- COSO: CA-03-02 검증·조정, CA-03-06 독립 검토, CE-03-03 윤리 교육 실시
- 탐지 기법(SQL 형태, 원본 분류): 누락·부재 — 필수 필드 NULL `WHERE required_col IS NULL`, 검증 로그 부재 `LEFT JOIN audit WHERE id IS NULL`, 증빙 파일 부재 `WHERE attachment IS NULL`, 역조건 존재 `WHERE cancel='Y' AND amount > 0`
- SQL 대입: 가능

## 수법

- 클레임 지불 전 프로모션 이벤트가 실제로 발생했는지 확인하지 않음
- 여러 프로모션에 걸쳐 누적 인센티브 수량 확인 안 함
- 벤더 검증 프로세스의 위험 신호 무시
- 대리인이 계약 수량을 초과하는 것을 감지 없이 허용
- 알려진 이상 사항을 준수 또는 감사 팀에 보고하지 않음
- 지급 실패 또는 계좌 불일치 후속 조치 안 함

## 탐지 방법

- 모든 고가 승인에 필수 검증 문서화 구현
- 승인 패턴 추적 — 비정상적으로 높은 통과율을 가진 승인자 플래그
- 부서 수준 부정 발생률을 선구자 지표로 모니터링
- 승인된 거래의 무작위 감사 샘플링 구현
- _whistleblower_ 채널 설정 및 보고율 추적

## 질의 골격 (원본)

- SQL: `LEFT JOIN audit WHERE id IS NULL`
- SPARQL(참고, 이 환경에는 KG 가 없다): `?e a dpsc:ExpenseClaim . OPTIONAL { ?e dpsp:hasEvidenceCheck ?ec } . FILTER(!BOUND(?ec))`
