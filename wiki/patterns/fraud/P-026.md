# P-026 채널 스투핑

- 위험 구분: **부정(고의)** — 일부러 규정·통제를 어기거나 숨긴 행위다. 예외 조건에 고의성 신호를 넣는다(`wiki/patterns/index.md` 2절).
- 설명: 최종 고객 수요 없이 대리점 또는 채널에 재고를 강제로 밀어넣어 단기 매출을 부풀리기. 실제 판매 없이 대리점에 대량 출고하고, 반품 조건을 은폐하며, 기간 말 매출 목표를 달성하기 위해 채널에 재고를 과다 공급함
- ACFE: Revenue Recognition Fraud (3)
- COSO: RA-01-03 위험 식별 프로세스, RA-02-01 영향 분석, RA-02-03 위험 매트릭스
- 탐지 기법(SQL 형태, 원본 분류): 임계 초과 — 누적 임계 초과 `WHERE SUM(col) OVER (...) > limit`
- SQL 대입: 가능

## 수법

- 최종 고객 수요 없이 대리점에 재고 강제 출고
- 반품 조건을 은폐한 대량 출고
- 기간 말 매출 목표 달성을 위한 채널 스투핑
- 가짜 주문으로 매출 부풀리기

## 탐지 방법

- 출고량과 실제 Sell-Thru(도소매 판매량) 간 불일치 분석
- 대리점별 재고 축적량 모니터링
- 기간 말 출고 급증 패턴 감지
- 반품률과 출고량 간 상관관계 분석

## 질의 골격 (원본)

- SQL: `{ SELECT (SUM(?a) AS ?total) WHERE { ?x dpsp:amount ?a } } FILTER(?total > ?limit)`
- SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:amount ?amt . { SELECT (SUM(?a) AS ?total) WHERE { ?x dpsp:amount ?a } } FILTER(?total > ?limit)`

## OKF 대입 힌트 (자동 생성)

- 후보 도메인: [영업마케팅 매출](okf/domains/sales.md)

## 대입 예시: 기간 말 매출 후 반품

- 대상 업무 흐름: 청구 → 정정 또는 반품
- 모집단: 기간마다 마지막 3일에 발행된 정상 청구
- 예외 조건: 다음 기간 첫 30일 안에 같은 청구를 정정하거나 반품한 건
- 정상 업무 제외: 품질 불량처럼 사유가 기록된 반품(사유 코드가 있으면)
- 기준 날짜: 청구 날짜
- 이름 규칙: 「<기간> 기간 말 3일 매출 중 다음 기간 초 반품된 거래」
- 쉬운 설명 문장: 기간 마지막에 잡힌 매출이 다음 기간 초에 되돌려진 거래를 찾는다. 실적을 맞추려고 미리 매출을 잡았을 가능성을 본다
- 조사할 증빙: 반품 승인서, 출고와 입고 증빙, 영업 실적 마감 자료
