# 데이터 이상징후 패턴: 임계 초과 (P-105 ~ P-110)

값이 기준·평소 범위·업무상 상한을 넘는 신호이다. 원본 패턴 정의(설명, 수법, 탐지 방법, COSO, 원본 질의 골격)와 Bottom-up 에서 쓰는 법(수준, 탐지 수단, 점검 질의 열 조건, OKF 에서 찾는 곳, 자주 묶이는 패턴)을 패턴마다 함께 적었다. 조합 규칙은 `wiki/patterns/index.md` 4절이다.

## P-105 절대 임계 초과

- 설명: 필드 값이 사전에 정의된 고정 임계값을 초과하는 경우. 예를 들어 거래 금액이 500만 원을 초과하거나, 할인율이 30%를 초과하는 경우 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-01 승인 통제, CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col > fixed_threshold`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:amount ?amt . FILTER(?amt > 5000000)`
- 수법: 금액 임계값 초과 / 비율 임계값 초과 / 건수 임계값 초과
- 탐지 방법: 임계값 기반 규칙 엔진 구성 / 임계값 초과 시 자동 승인 워크플로우 트리거 / 임계값 조정 이력 모니터링
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P105` — 기준 금액 테이블(예: `TI_GRPB_COMPANY_AUDIT_AMT`)이 있을 때만
  - 점검 질의 열 조건: `CASE WHEN <금액> > <기준 테이블의 기준 금액> THEN 1 ELSE 0 END` (숫자를 지어내지 않는다)
  - 찾는 곳(OKF): 기준 금액이 테이블로 있으면 그 값을 쓴다(예: `APPADAMSUSER.TI_GRPB_COMPANY_AUDIT_AMT` 시나리오법인별 사고금액 적용기준). 고정 숫자를 지어내지 않는다.
  - 자주 묶이는 패턴: P-130 집중도 이상, P-122 완전 중복

## P-106 통계적 임계 초과

- 설명: 필드 값이 통계적 분포 (평균 ± 표준편차) 에서 벗어나는 경우. 예를 들어 평균에서 2 표준편차 이상 벗어난 거래 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-03-04 실적을행 비교
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE ABS(col-avg)/std > 2`  (참고용. 실제 범위 밖 판정은 통계 도구 기준, `stat-views.md` 2절)
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:amount ?amt . { SELECT (AVG(?a) AS ?avg) (STDDEV(?a) AS ?std) WHERE { ?x dpsp:amount ?a } } FILTER((ABS(?amt-?avg)/?std) > 2)`
- 수법: Z-score 기반 이상치 탐지 / 이동 평균 대비 편차 감지 / 교대/부서별 통계적 비교
- 탐지 방법: 통계적 분포 기반 임계값 동적 설정 / 실시간 Z-score 계산 및 플래그 / 시간 경과에 따른 분포 변화 모니터링
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `stat_screen` 같은 대상의 평소, 같은 조건 안(B1_RECORD, B2_RECORD)
  - 찾는 곳(OKF): `has:amount` 거래 테이블의 금액. 범위 밖 판정은 SQL 로 직접 계산하지 않고 `stat_screen` 으로 한다.
  - 자주 묶이는 패턴: P-113 비정상 단축, P-122 완전 중복, P-130 집중도 이상

## P-107 비율 임계 초과

- 설명: 두 필드 간 비율이 사전 정의된 임계값을 초과하는 경우. 예를 들어 반품률이 20%를 초과하거나, 할인 비율이 정상 범위를 벗어날 때 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-03-04 실적을행 비교
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col_a/col_b > ratio`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:num ?n . ?s dpsp:den ?d . FILTER(?n/?d > 0.20)`
- 수법: 금액 비율 임계 초과 / 비율 추세 변화 감지 / 부서/제품군별 비율 비교
- 탐지 방법: 비율 계산 로직 자동화 / 비율 임계값 기반 경고 규칙 설정 / 비율 변화 추세 모니터링
- 쓰는 법:
  - 수준: 행·집단
  - 탐지 수단: `stat_screen` 비율 모드(denominator_column), 동료 대비 비율(B1_RATIO, B2_RATIO)
  - 찾는 곳(OKF): 두 금액·수량의 비율(할인/총액, 반품/판매). 분모 0 은 `NULLIF` 로 뺀다.
  - 자주 묶이는 패턴: P-129 분포 편차, P-130 집중도 이상

## P-108 누적 임계 초과

- 설명: 특정 기간 또는 그룹 내 누적 값이 임계값을 초과하는 경우. 예를 들어 대리인별 누적 인센티브가 공급 한도를 초과하거나, 월간 누적 청구 금액이 예산을 초과할 때 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-01 승인 통제, CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE SUM(col) OVER (...) > limit`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:amount ?amt . { SELECT (SUM(?a) AS ?total) WHERE { ?x dpsp:amount ?a } } FILTER(?total > ?limit)`
- 수법: 기간별 누적 금액 초과 / 그룹별 누적 건수 초과 / 롤링 누적 임계 초과
- 탐지 방법: 파티션별 누적 합계 계산 / 누적 임계값 초과 시 자동 플래그 / 누적 패턴 추세 분석
- 쓰는 법:
  - 수준: 집단
  - 탐지 수단: 이상징후 점검 질의 열 `R_P108` — 한도 컬럼·한도 테이블(계약 금액, 예산)이 있을 때만
  - 점검 질의 열 조건: 인라인 뷰에서 `SUM(<금액>) OVER (PARTITION BY <차원>) > <한도>` 인 행
  - 찾는 곳(OKF): 업체·거래선별 누적 금액과 한도(계약 금액, 예산)의 비교. 예: 계약 마스터 `TI_BQMS026_INFA_CTRT`.
  - 자주 묶이는 패턴: P-130 집중도 이상, P-103 논리적 관계 위반

## P-109 극단값 탐지

- 설명: 필드 값이 분포의 극단값 (예: 상위 1%) 에 해당하는 경우. 예를 들어 거래 금액이 상위 1퍼센타일을 초과하거나, 할인율이 극단적으로 높은 경우 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-03-04 실적을행 비교
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col >= PERCENTILE(0.99)`  (참고용. 실제 범위 밖 판정은 통계 도구 기준, `stat-views.md` 2절)
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:amount ?amt . { SELECT (?p99 AS ?p) WHERE { ?x dpsp:amount ?a . BIND(percentile(?a, 0.99) AS ?p) } } FILTER(?amt >= ?p)`
- 수법: 상위 1% 임계값 초과 / 하위 1% 임계값 미만 / 양측 극단값 탐지
- 탐지 방법: 퍼센타일 기반 임계값 동적 계산 / 극단값 발생 빈도 모니터링 / 극단값의 비즈니스 정당성 검증
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `stat_screen` B1_RECORD, B2_RECORD 의 상한 초과 쪽(P-106 과 함께 표시)
  - 찾는 곳(OKF): `PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY 금액)` 이상인 건.
  - 자주 묶이는 패턴: P-106 통계적 임계 초과, P-130 집중도 이상

## P-110 범위 상한 초과

- 설명: 필드 값이 비즈니스 논리상 가능한 최대 범위를 초과하는 경우. 예를 들어 시작일이 종료일보다 늦거나, IP 주소 범위가 논리적으로 불가능한 경우 탐지
- 기법 분류: P-02 임계 초과
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col > logical_max`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:ipStart ?s . ?s dpsp:ipEnd ?e . FILTER(?s > ?e)`
- 수법: 논리적 최대값 초과 / 물리적 한계 초과 / 비즈니스 규칙 위반
- 탐지 방법: 비즈니스 논리 기반 범위 정의 / 범위 위반 시 자동 거부 또는 경고 / 범위 규칙 정기 검토 및 업데이트
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P110`
  - 점검 질의 열 조건: `CASE WHEN <비율> > 1 OR <수량> > <업무상 상한> THEN 1 ELSE 0 END` (상한은 테이블 문서·업무 규칙에 있을 때만)
  - 찾는 곳(OKF): 업무상 불가능한 최댓값(비율 1 초과, 수량 상한).
  - 자주 묶이는 패턴: P-133 논리 범위 위반
