# 데이터 이상징후 패턴: 시간·순서 (P-111 ~ P-116)

날짜·시각의 순서가 뒤바뀌거나 간격이 비정상적으로 짧거나 긴 신호이다. 원본 패턴 정의(설명, 수법, 탐지 방법, COSO, 원본 질의 골격)와 Bottom-up 에서 쓰는 법(수준, 탐지 수단, 점검 질의 열 조건, OKF 에서 찾는 곳, 자주 묶이는 패턴)을 패턴마다 함께 적었다. 조합 규칙은 `wiki/patterns/index.md` 4절이다.

## P-111 선후 순서 위반

- 설명: 이벤트 간 선후 관계가 논리적으로 위반된 경우. 예를 들어 승인일이 이벤트 시작일보다 늦거나, 출고일이 주문일보다 빠른 경우 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-03-04 실적을행 비교
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE event_a_date > event_b_date`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?promo a dpsc:Promotion . ?promo dpsp:approvedDate ?app . ?event a dpsc:MarketingEvent . ?event dpsp:eventStartDate ?start . FILTER(?app > ?start)`
- 수법: 승인 전 이벤트 실행 / 출고 전 주문 미생성 / 결제 전 서비스 제공
- 탐지 방법: 이벤트 순서 검증 규칙 정의 / 순서 위반 시 자동 경고 / 순서 변경 이력 감사 추적
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P111`, `stat_screen` 간격 모드에서 대상 값이 음수인 하한 미만, `find_number_gaps` 번호 날짜 역전
  - 점검 질의 열 조건: `CASE WHEN <앞 단계 시각> > <뒤 단계 시각> THEN 1 ELSE 0 END` (같은 형식 문자열끼리 비교)
  - 찾는 곳(OKF): 같은 건의 단계별 시각. 예: `TI_BQMS005_INFA_QT` 의 `제출HQ` > `마감HQ`(VARCHAR2(14) 시각 문자열), 행사 시작일 > 예산 승인일.
  - 자주 묶이는 패턴: P-113 비정상 단축, P-129 분포 편차

## P-112 기간 역전

- 설명: 시작일이 종료일보다 늦는 등 기간이 역전된 경우. 예를 들어 계약의 시작일이 종료일보다 늦거나, 프로모션 기간이 논리적으로 불가능한 경우 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE start_date > end_date`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s a dpsc:Contract . ?s dpsp:startDate ?s . ?s dpsp:endDate ?e . FILTER(?s > ?e)`
- 수법: 계약 기간 역전 / 프로모션 기간 역전 / 프로젝트 기간 역전
- 탐지 방법: 기간 필드 간 순서 검증 / 기간 역전 시 자동 거부 / 기간 수정 이력 모니터링
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P112`
  - 점검 질의 열 조건: `CASE WHEN <시작일> > <종료일> AND <종료일> <> '00000000' THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): `has:validity-period` 테이블의 시작·종료 컬럼. 예: `TI_BQMS026_INFA_CTRT` 의 `CTR_DATE_START` > `CTR_DATE_END`. 종료일 플레이스홀더(`00000000`)는 뺀다.
  - 자주 묶이는 패턴: P-113 비정상 단축, P-129 분포 편차

## P-113 비정상 단축

- 설명: 두 이벤트 간 간격이 최소 허용 기간보다 짧은 경우. 예를 들어 프로모션 시작일과 종료일이 동일하거나, 승인에서 실행까지의 시간이 비정상적으로 짧은 경우 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE (date_b - date_a) < min`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s a dpsc:Promotion . ?s dpsp:fromDate ?f . ?s dpsp:toDate ?t . FILTER(?f = ?t)`
- 수법: 동일일 시작/종료 / 최소 기간 미만 실행 / 비정상적으로 빠른 승인-실행 간격
- 탐지 방법: 최소 기간 규칙 정의 / 기간 단축 건수 모니터링 / 비정상 단축 건수 추이 분석
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `stat_screen` 간격 모드(date_column=시작, metric_column=끝)의 하한 미만
  - 찾는 곳(OKF): 시작일과 종료일이 같은 행사·프로모션(기존 시나리오 「1일 프로모션」 SP_SA_SSA2004002 와 겹치지 않게).
  - 자주 묶이는 패턴: P-111 선후 순서 위반, P-106 통계적 임계 초과, P-130 집중도 이상

## P-114 비정상 지연

- 설명: 두 이벤트 간 간격이 최대 허용 기간을 초과하는 경우. 예를 들어 주문에서 출고까지 60일 이상 소요되거나, 승인에서 실행까지 비정상적으로 긴 시간이 소요될 때 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE (date_b - date_a) > max`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:dateA ?a . ?s dpsp:dateB ?b . FILTER((?b - ?a) > 60)`
- 수법: 최대 기간 초과 지연 / 정상 처리 시간 대비 과도한 지연 / 반복적 지연 패턴
- 탐지 방법: 최대 기간 규칙 정의 / 지연 건수 및 기간 모니터링 / 지연 원인 분석 및 개선 활동
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `stat_screen` 간격 모드의 상한 초과
  - 찾는 곳(OKF): 단계 사이 일수가 긴 건. 예: 발주(`TI_BQMS_PO_PO_MST`) → 입고(`TI_BQMS_GR_MST`) 조인 문서가 있는 흐름.
  - 자주 묶이는 패턴: P-104 참조 무결성 위반, P-129 분포 편차

## P-115 순서 위반

- 설명: 이벤트 단계 순서가 예상 순서와 일치하지 않는 경우. 예를 들어 결제 단계가 주문 단계보다 먼저 실행되거나, 검수 단계가 납품 단계보다 빠른 경우 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE sequence != expected`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s a dpsc:Transaction . ?s dpsp:step1 ?a . ?s dpsp:step2 ?b . ?s dpsp:step3 ?c . FILTER(?a > ?b)`
- 수법: 워크플로우 단계 순서 위반 / 승인 단계 생략 / 검증 단계 미실행
- 탐지 방법: 표준 워크플로우 순서 정의 / 순서 위반 시 자동 경고 / 순서 변경 이력 감사
- 쓰는 법:
  - 수준: 흐름·행
  - 탐지 수단: `find_number_gaps` 결번(번호 순서의 빈 곳)
  - 찾는 곳(OKF): PR > 입찰/견적 > 선정 > 발주 > 계약 > 입고 > 정산 순서(`okf/domains/bid-qt.md`)가 뒤바뀐 건.
  - 자주 묶이는 패턴: P-117 식별자 중복, P-111 선후 순서 위반

## P-116 동기화 역전

- 설명: 서로 다른 시스템 간 시간 기록이 역전된 경우. 예를 들어 시스템 A의 타임스탬프가 시스템 B의 타임스탬프보다 늦거나, 로그 기록 순서가 역전된 경우 탐지
- 기법 분류: P-03 시간·순서
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-04-05 응용 통제
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE sys_a.time > sys_b.time`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:sysATime ?a . ?s dpsp:sysBTime ?b . FILTER(?a > ?b)`
- 수법: 시스템 간 타임스탬프 불일치 / 로그 기록 순서 역전 / 동기화 지연으로 인한 시간 차이
- 탐지 방법: 시스템 간 시간 동기화 상태 모니터링 / 타임스탬프 비교 검증 / 동기화 지연 이벤트 알림
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P116`
  - 점검 질의 열 조건: `CASE WHEN <시스템 A 시각> > <시스템 B 시각> THEN 1 ELSE 0 END` (적재 컬럼 `LOAD_*` 는 업무 시각이 아니다)
  - 찾는 곳(OKF): 한국 시각과 현지 시각 컬럼 쌍(예: `TI_BQMS005_INFA_QT` 의 `요청HQ` 와 `"LOCAL 요청일시"`)의 역전. 적재 컬럼(`LOAD_*`)은 업무 시각이 아니다.
  - 자주 묶이는 패턴: P-111 선후 순서 위반
