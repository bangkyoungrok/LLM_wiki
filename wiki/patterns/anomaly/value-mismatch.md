# 데이터 이상징후 패턴: 값 불일치 (P-101 ~ P-104)

같은 행이나 연결된 두 테이블의 값이 서로 맞지 않는 신호이다. 원본 패턴 정의(설명, 수법, 탐지 방법, COSO, 원본 질의 골격)와 Bottom-up 에서 쓰는 법(수준, 탐지 수단, 점검 질의 열 조건, OKF 에서 찾는 곳, 자주 묶이는 패턴)을 패턴마다 함께 적었다. 조합 규칙은 `wiki/patterns/index.md` 4절이다.

## P-101 필드간 값 불일치

- 설명: 동일 엔티티 내 두 필드 간 값이 논리적으로 일치하지 않는 경우. 예를 들어 입력된 금액과 계산된 금액이 다르거나, 두 필드 간 비교 시 예상과 다른 결과가 나오는 경우 탐지
- 기법 분류: P-01 값 불일치
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col_a != col_b`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:colA ?a . ?s dpsp:colB ?b . FILTER(?a != ?b)`
- 수법: 동일 레코드 내 동명 필드 간 값 불일치 / 입력값과 계산값 간 불일치 / 관련 필드 간 논리적 관계 위반
- 탐지 방법: 동일 엔티티 내 비교 가능한 필드 간 값 검증 / 필드 간 일관성 규칙 정의 및 자동 검증 / 불일치 발생 시 경고 플래그 및 수동 검토 프로세스
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P101`
  - 점검 질의 열 조건: `CASE WHEN ABS(<총액> - <단가> * <수량>) > 0.01 THEN 1 ELSE 0 END` (계산 관계는 테이블 문서와 값 확인으로 정한다)
  - 찾는 곳(OKF): 같은 테이블 안에서 계산 관계가 있는 컬럼(총액 = 단가 × 수량, 원화 = 외화 × 환율). 예: `APPADAMSUSER.TI_BQMS005_INFA_QT` 의 `제출단가`, `예상수량`, `LOCAL_AMT`(관계는 테이블 문서와 값 확인으로 정한다).
  - 자주 묶이는 패턴: P-106 통계적 임계 초과, P-130 집중도 이상

## P-102 테이블간 조인 불일치

- 설명: 여러 테이블을 조인할 때 관련 필드 간 값이 일치하지 않는 경우. 예를 들어 주문 테이블과 배송 테이블의 금액이 다르거나, 거래 내역과 계좌 기록 간 불일치 탐지
- 기법 분류: P-01 값 불일치
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `JOIN ... WHERE a.col != b.col`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?x dpsp:hasY ?y . ?y dpsp:colA ?a . ?x dpsp:colB ?b . FILTER(?a != ?b)`
- 수법: 조인 키 기준 테이블 간 데이터 불일치 / 관련 테이블 간 금액/수량 불일치 / 분산 시스템 간 데이터 정합성 위반
- 탐지 방법: 관련 테이블 간 조인 검증 쿼리 실행 / 정기적 데이터 정합성 감사 / 조인 실패 또는 불일치 건수 모니터링
- 쓰는 법:
  - 수준: 흐름
  - 탐지 수단: `match_tables` 금액 불일치
  - 찾는 곳(OKF): 조인 문서가 있는(`usable: true`) 두 테이블의 같은 뜻 금액·수량 비교. `okf/joins/index.md` 에서 쌍을 고른다.
  - 자주 묶이는 패턴: P-130 집중도 이상, P-129 분포 편차

## P-103 논리적 관계 위반

- 설명: 필드 간 논리적 관계가 위반된 경우. 예를 들어 총액이 개별 금액의 합보다 작거나, 비율이 1을 초과하는 등 논리적으로 불가능한 값 탐지
- 기법 분류: P-01 값 불일치
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col_a < col_b (A≥B여야 함)`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:colA ?a . ?s dpsp:colB ?b . FILTER(?a < ?b)`
- 수법: 총액 < 개별 금액 합계 / 비율 > 1.0 (논리적으로 불가능) / 상위 값이 하위 값보다 작은 경우
- 탐지 방법: 필드 간 논리적 관계 규칙 정의 / 관계 위반 시 자동 경고 및 검토 / 비즈니스 로직 기반 검증 규칙 적용
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P103`
  - 점검 질의 열 조건: `CASE WHEN <부분 값> > <전체 값> THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): 부분과 전체 관계 컬럼. 예: `TI_BQMS005_INFA_QT` 의 `요청업체수` ≥ `제출업체수` ≥ `선정업체수`.
  - 자주 묶이는 패턴: P-129 분포 편차, P-108 누적 임계 초과

## P-104 참조 무결성 위반

- 설명: 외부 참조 키가 해당 테이블에 존재하지 않는 경우. 예를 들어 주문의 고객 ID가 고객 테이블에 없거나, 거래의 벤더 ID가 벤더 테이블에 없는 경우 탐지
- 기법 분류: P-01 값 불일치
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `LEFT JOIN ... WHERE ref IS NULL`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:hasRef ?r . OPTIONAL { ?r a dpsc:RefClass } . FILTER(!BOUND(?r))`
- 수법: 외래 키가 참조 테이블에 없는 레코드 / 삭제된 엔티티를 참조하는 레코드 / 고아 레코드 (참조 대상이 없는 레코드)
- 탐지 방법: LEFT JOIN 후 NULL 검사 / 정기적 참조 무결성 감사 / 참조 무결성 제약 조건 설정
- 쓰는 법:
  - 수준: 흐름
  - 탐지 수단: `match_tables` 짝 없음(대상이 마스터·상위 건일 때)
  - 찾는 곳(OKF): 조인 문서 frontmatter 의 `match_ratio` 가 1.0 미만인 관계(조인 실측 근거 문서가 `okf/references/` 에 있으면 함께 본다). 자식 키가 부모에 없는 행.
  - 자주 묶이는 패턴: P-129 분포 편차, P-130 집중도 이상, P-123 필수 필드 NULL
