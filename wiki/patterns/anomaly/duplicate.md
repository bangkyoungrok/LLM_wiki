# 데이터 이상징후 패턴: 중복·동일인 (P-117 ~ P-122)

같은 기록·번호·증빙이 반복되거나 다른 역할·업체가 같은 값을 쓰는 신호이다. 원본 패턴 정의(설명, 수법, 탐지 방법, COSO, 원본 질의 골격)와 Bottom-up 에서 쓰는 법(수준, 탐지 수단, 점검 질의 열 조건, OKF 에서 찾는 곳, 자주 묶이는 패턴)을 패턴마다 함께 적었다. 조합 규칙은 `wiki/patterns/index.md` 4절이다.

## P-117 식별자 중복

- 설명: 고유해야 하는 식별자 (프로모션 번호, 주문 번호 등) 가 중복되어 있는 경우. 동일한 식별자로 여러 레코드가 존재할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `GROUP BY id HAVING COUNT(*) > 1`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s a dpsc:Promotion . ?s dpsp:promoNo ?n . { SELECT ?n (COUNT(?n) AS ?c) WHERE { ?x dpsp:promoNo ?n } GROUP BY ?n HAVING (?c > 1) }`
- 수법: 프로모션 번호 중복 / 주문 번호 중복 / 거래 ID 중복
- 탐지 방법: GROUP BY + HAVING COUNT(*) > 1 쿼리 / 식별자 중복 시 자동 경고 / 중복 식별자 발생 원인 분석
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `find_duplicates`(key_columns = 업무 키), `find_number_gaps` 번호 중복, 그레인 `near_key`
  - 찾는 곳(OKF): 그레인 판정이 `near_key` 인 테이블(`okf/references/grain-samples.md`, 테이블 문서 그레인 블록) — 업무 키가 있는데 중복 행이 있다.
  - 자주 묶이는 패턴: P-122 완전 중복, P-130 집중도 이상

## P-118 연락처 중복

- 설명: 은행 계좌번호, 전화번호, 이메일 등 연락처 정보가 여러 엔티티에서 중복되어 있는 경우. 예를 들어 여러 벤더가 동일한 은행 계좌를 사용할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `GROUP BY acct_no HAVING COUNT(*) > 1`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `{ SELECT ?acct (COUNT(?acct) AS ?c) WHERE { ?v dpsp:bankAccount ?acct } GROUP BY ?acct HAVING (?c > 1) }`
- 수법: 은행 계좌번호 중복 / 전화번호 중복 / 이메일 주소 중복
- 탐지 방법: 연락처 필드별 중복 검사 / 중복 연락처 발생 시 소유주 확인 / 연락처 변경 이력 모니터링
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P118` — PII 컬럼은 값을 꺼내지 않고 조건에만 쓴다
  - 점검 질의 열 조건: 인라인 뷰에서 `COUNT(DISTINCT <업체 키>) OVER (PARTITION BY <연락처 컬럼>) > 1` 인 행
  - 찾는 곳(OKF): 계좌·전화·이메일은 PII 다. 값을 SELECT 하지 않고 `COUNT(DISTINCT 업체키)` 를 PII 컬럼으로 GROUP BY 한 건수만 쓰며, 시나리오 SQL 결과에는 업체 키만 낸다.
  - 자주 묶이는 패턴: P-121 교차 엔티티 일치, P-130 집중도 이상

## P-119 증빙 중복

- 설명: 영수증 번호, 송장 번호 등 증빙 자료가 여러 클레임에 중복 제출된 경우. 동일한 영수증으로 여러 번 청구할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-01 승인 통제, CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `GROUP BY invoice_no HAVING COUNT(*) > 1`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `{ SELECT ?inv (COUNT(?inv) AS ?c) WHERE { ?e dpsp:hasInvoice ?inv } GROUP BY ?inv HAVING (?c > 1) }`
- 수법: 영수증 번호 중복 / 송장 번호 중복 / 증빙 이미지 중복
- 탐지 방법: 증빙 번호별 중복 검사 / 증빙 이미지 해시값 비교 / 중복 증빙 발생 시 자동 거부
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `find_duplicates`(key_columns 에 증빙·인보이스 번호)
  - 찾는 곳(OKF): 인보이스·증빙 번호 컬럼(기존 시나리오 SP_SA_SSA2004009 와 겹치지 않게).
  - 자주 묶이는 패턴: P-122 완전 중복, P-130 집중도 이상

## P-120 역할 중복

- 설명: 요청자와 승인자가 동일한 경우. 예를 들어 자신이 요청한 거래를 자신이 승인하거나, 같은 직위가 여러 역할을 겸임할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-05 책임 분리
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE requester = approver`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?t a dpsc:Transaction . ?t dpsp:requester ?r . ?t dpsp:approver ?a . FILTER(?r = ?a)`
- 수법: 자기 승인 / 요청-승인 역할 겸임 / 권한 남용
- 탐지 방법: 요청자-승인자 비교 검증 / 역할 겸임 감지 / 책임 분리 규칙 강제
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P120`
  - 점검 질의 열 조건: `CASE WHEN <요청자·작성자> = <승인자·결재자> THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): 요청자·작성자와 승인자·결재자 컬럼 쌍. 예: BQMS 결재 테이블(`TI_BQMS012_APPROVAL_QT`, `TI_BQMS013_APPROVAL_BD`), `TI_BQMS005_INFA_QT` 의 `PR_USER_ID` 와 `견적담당ID`. 컬럼 뜻은 테이블 문서로 확인한다.
  - 자주 묶이는 패턴: P-129 분포 편차, P-130 집중도 이상
- 원본 대입 예시(작성자와 결재자 동일, 참고): 대상 업무 흐름: 전표나 품의의 작성과 결재 / 모집단: 기간 안에 결재가 끝난 전표 또는 품의 전체 / 예외 조건: 작성자와 결재자가 같은 사용자인 건 / 정상 업무 제외: 시스템 자동 결재처럼 사람이 결재하지 않는 건(구분 값이 있으면) / 기준 날짜: 결재 날짜 / 이름 규칙: 「<기간> 전표 중 작성자가 직접 결재한 건」 / 쉬운 설명 문장: 자기가 만든 전표를 자기가 승인한 건을 찾는다. 견제 없이 처리된 거래를 본다 / 조사할 증빙: 결재 기록, 권한 부여 내역, 위임 전결 규정

## P-121 교차 엔티티 일치

- 설명: 서로 다른 엔티티 간 필드 값이 일치하는 경우. 예를 들어 서로 다른 거래가 동일한 IP 주소를 사용할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE a.col = b.col`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?x dpsp:ip ?ip . ?y dpsp:ip ?ip2 . FILTER(?x != ?y && ?ip = ?ip)`
- 수법: 동일 IP 주소 사용 / 동일 기기 식별자 / 동일 네트워크 범위
- 탐지 방법: 교차 엔티티 필드 매칭 검증 / 일치 건수 및 패턴 분석 / 정상 일치와 비정상 일치 구분
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P121`
  - 점검 질의 열 조건: 인라인 뷰에서 `COUNT(DISTINCT <업체 키>) OVER (PARTITION BY <공유 값>) > 1` 인 행(예: 같은 `제출IP`, PII 아님을 문서로 확인)
  - 찾는 곳(OKF): 서로 다른 업체가 같은 값을 쓴 건. 예: `TI_BQMS005_INFA_QT` 의 `제출IP`, `SUBMIT_PROXY_IP`(비고 PII 가 아님을 문서로 확인). 기존 시나리오 「동일장소에서 견적 제출」 SP_BQ_SSA1802008 과 겹치지 않게.
  - 자주 묶이는 패턴: P-118 연락처 중복, P-130 집중도 이상

## P-122 완전 중복

- 설명: 여러 필드 값이 완전히 중복되어 동일한 거래가 반복 기록된 경우. 예를 들어 금액, 날짜, 벤더, 설명이 모두 동일한 복수 레코드가 존재할 때 탐지
- 기법 분류: P-04 중복·동일인
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE EXISTS (SELECT 1 FROM t2 ...)`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s a dpsc:Record . ?s dpsp:col1 ?c1 . ?s dpsp:col2 ?c2 . ?s2 a dpsc:Record . ?s2 dpsp:col1 ?c1 . ?s2 dpsp:col2 ?c2 . FILTER(?s < ?s2)`
- 수법: 전체 필드 중복 / 핵심 필드 중복 / 시간 간격 없는 반복 거래
- 탐지 방법: 전체 레코드 비교를 통한 중복 감지 / EXISTS 기반 중복 검사 / 중복 제거 및 원인 분석
- 쓰는 법:
  - 수준: 행
  - 탐지 수단: `find_duplicates` 완전 중복, 유사 중복
  - 찾는 곳(OKF): 금액·날짜·업체·품목이 모두 같은 행. 그레인 키가 다른데 업무 값이 같은 행.
  - 자주 묶이는 패턴: P-130 집중도 이상, P-119 증빙 중복, P-106 통계적 임계 초과
