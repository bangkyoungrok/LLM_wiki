# 데이터 이상징후 패턴: 형식·값 이상 (P-132 ~ P-135)

값의 형식이나 업무상 가능한 범위가 틀린 신호이다. 원본 패턴 정의(설명, 수법, 탐지 방법, COSO, 원본 질의 골격)와 Bottom-up 에서 쓰는 법(수준, 탐지 수단, 점검 질의 열 조건, OKF 에서 찾는 곳, 자주 묶이는 패턴)을 패턴마다 함께 적었다. 조합 규칙은 `wiki/patterns/index.md` 3절이다.

## P-132 형식 불일치

- 설명: 필드 값이 예상 형식과 일치하지 않는 경우. 예를 들어 IP 주소 형식이 잘못되거나, 날짜 형식이 표준과 다르고, 전화번호 형식이 불일치할 때 탐지
- 기법 분류: P-07 형식·값 이상
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- 이 기법을 쓰는 부정 패턴(Top-down 참고): P-004 영수증/송장 위조 및 중복 청구, P-011 계정 및 자격증명 공유, P-015 개발 IP 및 자원 유출
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col NOT REGEXP 'pattern'`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:ip ?ip . FILTER(!REGEX(?ip, '^(\d{1,3}\\.){3}\d{1,3}$'))`
- 수법: IP 주소 형식 오류 / 날짜 형식 불일치 / 이메일 형식 오류
- 탐지 방법: 정규식을 통한 형식 검증 / 형식 불일치 건수 모니터링 / 형식 규칙 정기 검토
- Bottom-up 에서 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P132`
  - 점검 질의 열 조건: `CASE WHEN <날짜 문자열> <> '00000000' AND NOT REGEXP_LIKE(<날짜 문자열>, '^[0-9]{8}$') THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): VARCHAR2 날짜 컬럼이 형식(`^[0-9]{8}$`)에 맞지 않는 값(`REGEXP_LIKE`), 코드 형식 위반. 플레이스홀더 `00000000` 은 따로 센다.
  - 자주 묶이는 패턴: P-123 필수 필드 NULL, P-129 분포 편차

## P-133 논리 범위 위반

- 설명: 필드 값이 논리적으로 가능한 범위 (최소/최대) 를 벗어나는 경우. 예를 들어 비율이 1.0을 초과하거나, 할인율이 음수일 때 탐지
- 기법 분류: P-07 형식·값 이상
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- 이 기법을 쓰는 부정 패턴(Top-down 참고): P-004 영수증/송장 위조 및 중복 청구, P-011 계정 및 자격증명 공유, P-015 개발 IP 및 자원 유출
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col < min OR col > max`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:ratio ?r . FILTER(?r > 1.0)`
- 수법: 비율 > 1.0 / 음수 할인율 / 허용 범위 이탈
- 탐지 방법: 비즈니스 논리 기반 범위 정의 / 범위 위반 자동 검증 / 범위 규칙 업데이트 프로세스
- Bottom-up 에서 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P133`
  - 점검 질의 열 조건: `CASE WHEN <금액> < 0 OR <비율> > 1 OR <수량> <= 0 THEN 1 ELSE 0 END` (정정·반품처럼 음수가 정상인 컬럼은 빼고 쓴다)
  - 찾는 곳(OKF): 음수 금액, 1 초과 비율, 0 이하 수량.
  - 자주 묶이는 패턴: P-110 범위 상한 초과, P-106 통계적 임계 초과

## P-134 변경값 무의미

- 설명: 필드 값이 변경되었으나 실제 변경이 없는 경우. 예를 들어 수정 전후 값이 동일하거나, 변경값이 0인 경우 탐지
- 기법 분류: P-07 형식·값 이상
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정
- 이 기법을 쓰는 부정 패턴(Top-down 참고): P-004 영수증/송장 위조 및 중복 청구, P-011 계정 및 자격증명 공유, P-015 개발 IP 및 자원 유출
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE new = old OR new = 0`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:beforeVal ?b . ?s dpsp:afterVal ?a . FILTER(?b = ?a)`
- 수법: 수정 전후 값 동일 / 변경값 0 / 의미 없는 자동 변경
- 탐지 방법: 수정 전후 값 비교 / 무의미 변경 건수 모니터링 / 변경 이력 감사
- Bottom-up 에서 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P134` — 이력 테이블(`_H`, `_HISTORY`)을 대상으로 할 때만
  - 점검 질의 열 조건: `CASE WHEN <변경 후 값> = <변경 전 값> OR <변경 후 값> = 0 THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): 이력 테이블(`_H`, `_HISTORY`)에서 변경 전후 값이 같은 변경 기록.
  - 자주 묶이는 패턴: P-129 분포 편차

## P-135 인코딩/특수문자

- 설명: 필드 값에 허용되지 않는 인코딩이나 특수문자가 포함된 경우. 예를 들어 이름 필드에 비정상 문자가 있거나, 설명 필드에 코드 주입 시도가 있을 때 탐지
- 기법 분류: P-07 형식·값 이상
- ACFE: N/A (기술적 탐지 패턴)
- COSO: CA-03-02 검증·조정, CA-04-05 응용 통제
- 이 기법을 쓰는 부정 패턴(Top-down 참고): P-004 영수증/송장 위조 및 중복 청구, P-011 계정 및 자격증명 공유, P-015 개발 IP 및 자원 유출
- SQL 대입: 가능
- 원본 질의 골격:
  - SQL: `WHERE col LIKE '%invalid%'`
  - SPARQL(참고, 이 환경에는 KG 가 없다): `?s dpsp:name ?n . FILTER(REGEX(?n, '[^a-zA-Z0-9가-힣\s]'))`
- 수법: 비정상 문자 포함 / 코드 주입 시도 / 인코딩 불일치
- 탐지 방법: 문자 인코딩 검증 / 특수문자 필터링 / 입력 값 sanitization
- Bottom-up 에서 쓰는 법:
  - 수준: 행
  - 탐지 수단: 이상징후 점검 질의 열 `R_P135`
  - 점검 질의 열 조건: `CASE WHEN REGEXP_LIKE(<텍스트 컬럼>, '[[:cntrl:]]') THEN 1 ELSE 0 END`
  - 찾는 곳(OKF): 업체명·품목명에 허용되지 않는 문자. 자유 텍스트 컬럼은 `REGEXP_LIKE` 로 본다.
  - 자주 묶이는 패턴: P-121 교차 엔티티 일치
