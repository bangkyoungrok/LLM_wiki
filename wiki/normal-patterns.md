# 정상 업무 패턴

이상처럼 보이지만 업무상 정상이거나 데이터 특성상 빼야 하는 경우의 목록이다. agent 는 시나리오 SQL 의 정상 업무 제외 조건과 반례 확인에 이 표의 SQL 조건을 그대로 쓴다. 테이블과 컬럼이 「미확인」인 행은 조건을 쓰기 전에 OKF 테이블 문서에서 해당 컬럼을 찾고, 찾지 못하면 「데이터 해석 가정」에 「정상 업무 제외 못 함」으로 적는다.

## 1. 데이터 특성 (OKF 규칙에서 옮김, 모든 영역)

| 이상처럼 보이는 현상 | 빼는 이유 | 해당 테이블 | SQL 조건 | 검토 상태 |
|---|---|---|---|---|
| 종료일이 비어 있거나 기간 이탈로 보이는 조건 | `'00000000'` 은 종료일 미정의 플레이스홀더다 (`okf/t2s/rules/soft-delete-validity.md`) | TI_GRPB_DE_PAYMENT_REPORT 등 종료일 컬럼이 있는 테이블 | `<종료일 컬럼> <> '00000000'` (TI_GRPB_DE_PAYMENT_REPORT 는 `CONDITION_TO`) | 자동 생성 |
| 비율·단가가 극단적으로 작거나 큼 | 계약 금액 1.0, 10,000 같은 플레이스홀더 금액이 섞여 있다 (`soft-delete-validity.md`, TI_GRPF005 T2S 힌트) | TI_GRPF005 등 | 테이블 문서 T2S 힌트의 플레이스홀더 값을 제외 | 자동 생성 |
| 삭제된 행이 예외로 잡힘 | `has:soft-delete` 테이블은 삭제 플래그가 켜진 행이 남아 있다 | `has:soft-delete` 태그 테이블 | 삭제 플래그 컬럼(Schema 확인) 정상값 조건. 값이 `Y/N` 인지 `0/1` 인지는 `okf/references/code-value-samples.md` | 자동 생성 |
| 같은 키가 여러 행(이력 증폭) | `has:validity-period` 테이블은 유효기간마다 행이 있다 | `has:validity-period` 태그 테이블 | 현재 유효 또는 기준일이 유효기간 안인 조건 | 자동 생성 |
| 공통코드가 중복·폐기 값으로 매칭됨 | 삭제된 공통코드가 남아 있다 | SETADAMSUSER.TC_CF_COMM_CODE | `DELETE_YN = '0'` | 자동 생성 |
| 시나리오 추출 결과·하이퍼스 테이블의 이상 | TR_ 시나리오 추출 테이블과 TI_HYBR 테이블은 조회 대상에서 제외됐다 (테이블 문서 그레인 블록의 「제외」 표기) | TR_*, TI_HYBR* | 이 테이블로 시나리오를 만들지 않는다 | 자동 생성 |
| 공사(SHR) 업무의 이상 | 공사 시나리오 참조 테이블은 AIAGT 접근 범위 밖이다 (`okf/references/scenarios.md`) | TI_BQMS3xx, TR_SHR* | 대입하지 않는다 | 자동 생성 |
| 같은 조회에서 행 수가 통계보다 매우 적음 | VPD·마스킹 정책 (`okf/t2s/rules/result-interpretation.md`) | 전체 | 조건 아님. 「데이터 해석 가정」에 적는다 | 자동 생성 |

## 2. 업무 패턴 (감사 wiki 기본안에서 옮김, 테이블 미확인)

| 이상처럼 보이는 현상 | 정상인 이유 | 해당 테이블 | SQL 조건 | 검토 상태 |
|---|---|---|---|---|
| 출고 기록이 없는 청구 | 서비스 품목은 출고가 없다 | 미확인 (매출 도메인 빌링·품목 테이블) | 미확인 (품목 유형 컬럼) | 자동 생성 |
| 기간 말 매출의 다음 기간 초 반품 | 품질 불량처럼 사유가 기록된 반품 | 미확인 (매출 조정·반품 테이블) | 미확인 (반품 사유 코드) | 자동 생성 |
| 입고 없는 반품 정정 | 금액만 바로잡는 정정은 입고가 없다 | 미확인 (Credit/Debit Memo) | 미확인 (정정 유형) | 자동 생성 |
| 승인 기준 바로 아래 할인 | 정책 할인은 승인 대상이 아니다 | 미확인 (판가 조건 TI_GRPB_PRICE_CONDITION 등) | 미확인 (할인 구분 코드) | 자동 생성 |
| 실적 미달 대상 판촉 지급 | 약정 변경 승인이 있는 지급 | 미확인 (마케팅비 지급·조건 테이블) | 미확인 (변경 기록) | 자동 생성 |
| 신규 거래처의 등록 직후 대량 거래 | 대형 계약으로 등록된 거래처 | 미확인 (업체 마스터 TN_AD_VENDOR, TI_BQMS800) | 미확인 (계약 구분) | 자동 생성 |
| 작성자와 결재자가 같음 | 시스템 자동 결재 | 미확인 (결재 테이블) | 미확인 (자동 결재 구분) | 자동 생성 |
| 마감 직전 실적의 마감 후 취소 | 고객 사정으로 사유가 기록된 취소 | 미확인 | 미확인 (취소 사유 코드) | 자동 생성 |
