# 시나리오 선별 기준 (Top-down)

Top-down 후보의 우선순위를 정하는 기준이다. 선별은 SQL 을 쓰기 전에 하므로 모든 점수를 wiki 와 OKF 문서 정보로 매긴다. 시험 실행 건수는 선별에 쓰지 않고 통과 여부(`AGENTS.md` 8절)에만 쓴다.

| 기준 | 2점 | 1점 | 0점(후보에서 뺌) |
|---|---|---|---|
| 위험 연결 | 부정 패턴 2개 이상의 조합이고(`wiki/patterns/index.md` 4절), 패턴의 위험과 수법을 그대로 대입하고, 고의성 신호(2절)를 예외 조건에 하나 이상 넣을 수 있음 | 단일 패턴, 패턴을 일부 바꿔 대입함, 또는 고의성 신호를 넣을 수 없음 | 패턴과 연결 없음 |
| 영향 규모 | 모집단 테이블에 `has:amount` 태그가 있고 `size:m` 이상(100만 행 이상) | 둘 중 하나 | 둘 다 없음 |
| 탐지 가능성 | 단일 테이블이거나 필요한 조인이 모두 조인 문서(`usable: true`)로 있고, 핵심 컬럼이 Schema 한글명·T2S 힌트로 분명함 | 문서 없는 조인(근거+실측 필요)이나 코드값 확인이 필요함 | 직접 조인 금지 쌍, `usable: false`, `cartesian_risk: m2m` 에만 기댐, 또는 핵심 컬럼이 테이블 문서에 없음 |
| 조사 가능성 | 예외 건마다 확인할 증빙을 특정할 수 있음(문서번호·요청번호 같은 키가 결과에 있음) | 일부만 특정 | 특정할 수 없음 |
| 오탐 통제 | 정상 업무를 조건으로 뺄 수 있음(`wiki/normal-patterns.md`, soft-delete, 플레이스홀더, 패턴 page 의 정상 업무 제외) | 일부만 뺄 수 있음 | 뺄 수 없음 |

합계(최대 10점)로 순위를 정한다. 같으면 아래 순서로 앞에 둔다.

1. 매출 인식 위험(ACFE Revenue Recognition Fraud: P-001, P-026, P-027, P-028)이 든 조합을 앞에 둔다. 감사 기준(ISA 240)이 매출 인식에 부정 위험이 있다고 전제하기 때문이다.
2. 조합의 부정 패턴 수가 많은 순.
3. 영향 규모(`row_count`)가 큰 순.

- 기존 시나리오(`wiki/examples/index.md`)와 탐지 조건이 같은 후보는 점수와 관계없이 뺀다(만들지 않은 후보, 사유: 기존 시나리오 <이름> 과 같음).
- 패턴 page 의 「SQL 대입」이 「불가(그래프)」·「도메인 없음」인 패턴은 후보와 조합에 넣지 않는다.
- 단일 패턴 후보는 조합 후보가 요청 건수보다 적을 때만 선별에 넣는다(`wiki/patterns/index.md` 4절).
