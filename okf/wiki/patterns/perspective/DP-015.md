# DP-015 소급·사후 증액 조건

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 조건 시점 — 판매가 끝난 뒤 조건을 만들거나 늘렸는가
- 사고 유형: ⑥ 편법지원/과소충당 (구두보상 약속) / ⑦
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 판매기간이 끝난 뒤 만들어지거나 증액된 지급 조건은, 거래선에 구두로 약속한 보상을 사후에 인센티브 명목으로 메우는 데 쓰인다. 조건 등록·변경 시점을 판매기간·지급일과 비교한다.
- 답하는 질문: 지급 조건이 판매기간 종료 뒤에 등록되었거나 지급 직전에 늘어났는가
- 관련 패턴(참고): [P-111 선후 순서 위반](okf/wiki/patterns/anomaly/P-111.md), [P-112 기간 역전](okf/wiki/patterns/anomaly/P-112.md), [P-008 시스템 제어 우회](okf/wiki/patterns/fraud/P-008.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 결과의 지급 조건 등록일이 판매기간보다 늦다
- 같은 거래선에 조건 변경이 잦다

## 고르지 않는 때

- 조건 등록일·변경일 컬럼이 없다

## 추출 로직

1. 유형 ① 소급 조건: 조건 등록일 > 판매기간 종료일. 등록 지연 일수를 낸다
2. 유형 ② 사후 증액: 판매기간 종료 뒤 또는 지급 직전에 조건 수량·단가가 위로 바뀜
3. 딜시트 발송 이력이 판매기간 이전에 있으면 「사전 합의 있음」으로 표시한다
4. 거래선별 ①② 건수와 반복 분기 수를 낸다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 법인 업무 관행상 조건 등록이 늦는 경우 — 등록 지연 일수 분포와 딜시트 사전 발송으로 구분한다
- 승인된 조건 변경

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 등록 지연 일수는 법인별 분포 상위만 남긴다

## 멈춤 기준

- 같은 거래선에서 반복되면 ⑥ 유형의 별도 시나리오로 넘긴다

## 질문 단서

> 직전 결과의 컨디션 가운데 판매기간이 끝난 뒤 등록되었거나 판매기간 종료 뒤 수량·단가가 늘어난 건을, 판매기간 전에 딜시트가 발송된 건은 빼고 뽑아 줘. 거래선별 반복 횟수도 보여 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 사고 유형 분류: ⑥ 구두보상 약속, 허위 명목의 가격·재고 보전 / ⑦ 가격 적용일 변경
- 관련 테이블: `TI_GRPF063`(컨디션 헤더: 계약기간, 승인정보), `TI_GRPF064`(컨디션 항목), `TI_GRPF065`(컨디션 딜시트: `DSTYP`, 발송정보)

## 확인 필요

- 컨디션 등록일·변경일 컬럼과 변경 이력 보유 여부
- 딜시트 발송일 컬럼
