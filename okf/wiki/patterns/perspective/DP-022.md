# DP-022 과지급 미회수·재발

- 묶음: **책임·사후관리** — 왜 걸러지지 않았는지(사람·통제)와 회수·회계 반영 여부를 본다
- 관점: 사후관리 — 과지급을 회수했고 다시 생기지 않았는가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (과지급금 미회수)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 과다지급의 손실은 회수되지 않을 때 확정된다. 과지급으로 판정된 건이 수량차감·회입으로 회수되었는지, 판정 뒤에도 같은 거래선·제품에 지급이 계속되었는지 보고, 유형 간 중복을 뺀 최종 회입 대상 금액을 확정한다.
- 답하는 질문: 과지급 판정 수량만큼 뒤에 차감·회입되었고, 판정 뒤 같은 대상에 지급이 멈췄는가
- 관련 패턴(참고): [P-124 검증 로그 부재](okf/wiki/patterns/anomaly/P-124.md), [P-127 지속 방향성 변화](okf/wiki/patterns/anomaly/P-127.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 직전 결과가 과지급 판정 건으로 특정되었다
- 보고서에 과거 점검 결과가 있다

## 고르지 않는 때

- 직전 결과가 아직 과지급 판정 단계가 아니다

## 추출 로직

1. 유형 ① 미회수: 과지급 판정 수량 − 판정 이후 수량차감 > 0. 경과 기간별로 나눈다
2. 유형 ② 재발: 초과 상태([DP-008](okf/wiki/patterns/perspective/DP-008.md)) 진입 뒤에도 계속 지급된 횟수·금액, 과거 점검 초과 KEY 가 지금도 초과인 경우
3. 유형 ③ 비공식 회수: 수량차감·회입 없이 다음 조건의 단가·수량을 낮춰 상쇄한 정황
4. 최종 회입 대상 금액 = 앞 판정의 과지급액(같은 지급 문서가 여러 판정에 걸리면 가장 큰 금액 1회) − 기회수액

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 거래 종료·폐업으로 회수 불가 — 손실 확정 건으로 따로 표시
- 금액을 다투는 분쟁 중 건 — 따로 표시

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 경과 기간 구분(분기·반기·1년)은 법인 정산 주기에 맞춘다

## 멈춤 기준

- 마지막 확인 단계다. 법인·거래선별 최종 회입 대상 금액과 미회수 잔액으로 멈춘다
- 앞에서 이미 멈췄어도 회수 확인만 따로 할 수 있다

## 함께 쓰기

- [DP-023](okf/wiki/patterns/perspective/DP-023.md) — 회계 반영과 함께 마무리할 때

## 질문 단서

> 직전 결과의 과지급 건마다 판정 이후 수량차감·회입 실적을 대조해 미회수 잔액과 경과 기간을 내고, 판정 뒤에도 같은 거래선·SKU 에 계속 지급된 건을 표시해 줘. 여러 판정에 걸린 지급 문서는 한 번만 세어 최종 회입 대상 금액을 계산해 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 제공 원본 점검시나리오: 이상건이 확정된 과지급 금액은 거래선으로부터 회입 진행
- 사고 유형 분류: ⑦ 과지급금 미회수

## 확인 필요

- DR 外 현금 회입이 기록되는 위치
- 과거 점검 결과 보관 위치
