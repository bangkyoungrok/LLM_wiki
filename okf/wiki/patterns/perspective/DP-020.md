# DP-020 처리 시점·지급 경로 이상

- 묶음: **책임·사후관리** — 왜 걸러지지 않았는지(사람·통제)와 회수·회계 반영 여부를 본다
- 관점: 처리·경로 — 지급이 이례적인 시점이나 다른 상대에게 처리되었는가
- 사고 유형: ② 업체 유착/특혜 (지급 상대가 다르면 ①)
- 대상 범위: **좁힘** — 직전 결과 안에서 조건을 더해 줄인다
- 설명: 지급 등록이 결산기 말·휴일·심야에 몰렸거나, 담당자 변경 직전에 몰렸거나, 지급 상대가 조건의 고객과 다른 코드인 건을 찾는다. 지급 상대가 다르면 자금이 다른 곳으로 흘렀을 가능성이 있다.
- 답하는 질문: 지급이 이례적인 시점에 등록되었거나 조건의 고객과 다른 상대에게 나갔는가
- 관련 패턴(참고): [P-129 분포 편차(업무 시간 외 입력)](okf/wiki/patterns/anomaly/P-129.md), [P-121 교차 엔티티 일치](okf/wiki/patterns/anomaly/P-121.md), [P-006 지급 채널 가로채기](okf/wiki/patterns/fraud/P-006.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- [DP-018](okf/wiki/patterns/perspective/DP-018.md) 에서 쏠림이 나왔다
- 결과의 지급 방식에 매출채권 상계가 아닌 별도 지급이 섞여 있다

## 고르지 않는 때

- 지급 등록 일시·전표 정보가 없다

## 추출 로직

1. 유형 ① 처리 시점: 결산기 말 집중, 휴일·업무 시간 외 등록, 담당자 변경 직전 집중
2. 유형 ② 지급 상대: 지급 상대 코드 ≠ 조건 고객 코드(매핑으로 연결되지 않음)
3. 유형 ③ 지급 방식: 매출채권 상계가 아닌 별도 지급의 비중이 거래선 평소보다 높음

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 결산 일정상 기간 말 처리가 몰리는 법인
- 매핑에 등록된 지급처(Payer)로의 지급

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 시점 집중 기준은 법인별 처리 시점 분포를 쓴다

## 멈춤 기준

- ② 가 나오면 유형을 ① 로 보고 실사로 넘긴다

## 함께 쓰기

- [DP-018](okf/wiki/patterns/perspective/DP-018.md), [DP-019](okf/wiki/patterns/perspective/DP-019.md)

## 질문 단서

> 직전 결과의 지급 가운데 지급 상대가 컨디션 고객과 매핑되지 않는 코드인 건, 결산기 말·휴일·업무 시간 외에 등록된 건, 상계가 아닌 별도 지급 비중이 평소보다 높은 거래선을 뽑아 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPF060`(지급 헤더: FI 전표 `BELNR`, 고객), `TI_GRPB_CUSTOMER_MAPPING`

## 확인 필요

- 지급 등록 일시 컬럼
- 지급 방식(상계·별도 지급)을 구분하는 전표 정보 위치
