# DP-014 조건 단가·한도 초과

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 계약 조건 — 계약 단가·수량·금액 한도 안에서 지급했는가
- 사고 유형: ④ 검증부실/과다지급 (단가·지급기준 오적용)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 수량이 맞아도 단가·한도·기간이 계약(지급 조건)과 다르면 과다지급이다. 지급 항목을 지급 조건과 연결해 단가 초과, 누적 한도 초과, 판매기간 밖 실적을 찾는다.
- 답하는 질문: 지급 단가·누적 수량·누적 금액·실적 기간이 지급 조건 안에 드는가
- 관련 패턴(참고): [P-101 필드간 값 불일치](okf/wiki/patterns/anomaly/P-101.md), [P-105 절대 임계 초과](okf/wiki/patterns/anomaly/P-105.md), [P-108 누적 임계 초과](okf/wiki/patterns/anomaly/P-108.md), [P-110 범위 상한 초과](okf/wiki/patterns/anomaly/P-110.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 수량 관점(A 묶음, [DP-008](okf/wiki/patterns/perspective/DP-008.md)~[DP-013](okf/wiki/patterns/perspective/DP-013.md))에서 설명되지 않는 초과 금액이 남는다
- 결과의 지급 단가가 같은 조건의 다른 지급보다 높다

## 고르지 않는 때

- 지급 조건의 단가 컬럼을 특정하지 못한다

## 추출 로직

1. 유형 ① 단가 초과: 지급 단가 > 조건 단가. 지급 항목의 변경 전·후 단가가 위로 바뀐 건 포함. 과지급액 = (지급 단가 − 조건 단가) × 지급수량
2. 유형 ② 한도 초과: 조건별 누적 지급수량 > 프로모션 수량, 또는 누적 지급금액 > 프로모션 비용. 한도를 처음 넘긴 지급 문서를 표시
3. 유형 ③ 기간 외 실적: 청구 대상 판매일이 조건의 판매기간 밖

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 수량 구간별 단가(Tier) — 달성 구간 단가로 비교한다
- 승인된 조건 변경 — 변경 승인 이력이 있으면 뺀다
- 통화가 다르면 같은 통화로 맞춘다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 단가 일치 허용 범위는 반올림 수준

## 멈춤 기준

- ①② 는 조건 초과분이 그대로 과지급이므로 멈출 수 있다

## 함께 쓰기

- [DP-015](okf/wiki/patterns/perspective/DP-015.md), [DP-016](okf/wiki/patterns/perspective/DP-016.md) — 「조건」 관점을 한 번에 볼 때

## 질문 단서

> 직전 결과의 지급 항목을 컨디션 항목과 연결해, 지급 단가가 조건 단가보다 높거나, 컨디션별 누적 지급수량·금액이 프로모션 수량·비용을 넘거나, 판매기간 밖 실적이 청구된 건을 뽑고 초과분 금액을 계산해 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPF061`(지급 항목: `PRICE`, `OLDPR`, `NEWPR`, `TCAMT`, `IVAMT`), `TI_GRPF064`(컨디션 항목: 조건 값, 프로모션 수량·비용), `TI_GRPF063`(계약기간)

## 확인 필요

- 조건 단가가 담긴 컬럼(컨디션 항목의 조건 값)
- Tier 단가 구분
