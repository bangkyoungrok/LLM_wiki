# DP-004 거래선 매핑 보정

- 묶음: **진위 판별** — 대사로 나온 초과가 진짜 초과인지, 기준·단위·표기 문제로 생긴 초과인지 가른다
- 관점: 거래선 기준 — 같은 거래선의 공급이 매핑에서 빠졌는가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (보정 후에도 초과면 ④)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 공급 쪽 거래선(주문처)과 지급 쪽 거래선(지급 고객)을 잇는 매핑에 실제 운영 코드가 일부만 등록되면, 공급이 과소집계되어 초과처럼 보인다. 같은 거래선으로 볼 수 있는 미등록 코드의 공급을 더해 다시 대사한다.
- 답하는 질문: 같은 거래선으로 볼 수 있는 코드의 공급까지 더해도 지급이 공급을 넘는가
- 관련 패턴(참고): [P-104 참조 무결성 위반](okf/wiki/patterns/anomaly/P-104.md), [P-121 교차 엔티티 일치](okf/wiki/patterns/anomaly/P-121.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 초과가 특정 거래선에 크고, 그 거래선의 거의 모든 제품에서 고르게 나타난다(공급 자체가 빠졌다는 신호)
- 초과 거래선의 매핑 등록 코드 수가, 같은 지급처·사업자등록번호를 가진 거래 중인 코드 수보다 적다
- 거래선 코드 변경·통폐합 이력이 있다

## 고르지 않는 때

- 매핑 대상이 처음부터 1:1(주문처 = 지급 고객)인 법인이다

## 추출 로직

1. 같은 거래선 후보 코드(매핑 미등록 코드 가운데): ① 지급처(Payer)·청구처(Bill-to)가 같은 주문처 ② 사업자등록번호·상위(본사) 코드가 같은 고객코드 ③ 고객코드 매핑정보에서 지급 고객과 연결된 코드
2. 보정 공급량 = 기존 누적 공급량 + 후보 코드의 같은 제품 누적 공급량([DP-001](okf/wiki/patterns/perspective/DP-001.md) 부호 규칙)
3. 보정 초과수량 = 누적 지급수량 − 보정 공급량(양수만)
4. 판정 ① 해소 → 「검증기준 오등록」, 결과에서 뺀다 / ② 유지 → 「과다청구 후보」, 남긴다
5. ① 로 판정된 거래선은 매핑 누락 기간의 지급액을 「미검증 지급」으로 따로 집계한다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 거래선 인수·합병, 코드 통폐합으로 구코드 공급과 신코드 지급이 갈린 경우 — 합산한다
- 거래선 사이의 재고 이관·재고 공유 — 양쪽을 합산한다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 후보 코드를 넓게 잡으면 진짜 초과가 묻힌다 → ①~③ 가운데 문서로 확인되는 관계만 쓰고, 이름 유사 같은 추정은 쓰지 않는다

## 멈춤 기준

- 보정 후 초과가 소수 거래선·제품으로 모이고 금액이 크면 과다청구 시나리오로 멈출 수 있다
- ① 의 미검증 지급액이 크면 검증기준 관리 미흡 시나리오로 멈출 수 있다

## 질문 단서

> 직전 결과의 초과 거래선마다, 매핑에는 없지만 같은 지급처·사업자등록번호를 가진 주문처 코드의 셀인을 더해 다시 비교하고, 그래도 셀아웃이 셀인을 넘는 건만 남겨 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- Risk 사례: ■■법인이 GSCM 상 CE 거래선 검증기준을 운영하면서 실운영 거래선코드 4개 중 1개만 등록, 셀인 과소측정으로 과지급 이상징후 발생
- Site Group 은 법인이 직접 등록·관리
- 관련 테이블: `TI_GRPB_CUSTOMER_MAPPING`(고객코드 매핑), `TI_GRPB004B`(빌링), `TI_GRPF060`(지급 헤더: 고객), `TI_GRPF064`(컨디션 항목: 고객)

## 확인 필요

- 지급처·청구처 등 파트너 정보, 사업자등록번호·상위코드가 있는 고객 마스터
- Site Group 매핑의 등록·변경 이력 보유 여부
