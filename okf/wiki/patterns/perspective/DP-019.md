# DP-019 직무분리 위반

- 묶음: **책임·사후관리** — 왜 걸러지지 않았는지(사람·통제)와 회수·회계 반영 여부를 본다
- 관점: 직무분리 — 등록·승인·지급을 한 사람이 처리했는가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (쏠림과 겹치면 ②)
- 대상 범위: **좁힘** — 직전 결과 안에서 조건을 더해 줄인다
- 설명: 지급 조건 등록, 정산 검증, 지급 승인이 한 사람 안에서 끝나면 과다지급을 막을 통제가 없다. 등록자·승인자·지급 처리자가 같은 건을 찾는다.
- 답하는 질문: 조건 등록자·승인자·지급 처리자가 같은 사람인가
- 관련 패턴(참고): [P-120 역할 중복](okf/wiki/patterns/anomaly/P-120.md), [P-008 시스템 제어 우회](okf/wiki/patterns/fraud/P-008.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 직전 결과에 등록자·승인자 정보가 있다
- [DP-018](okf/wiki/patterns/perspective/DP-018.md) 에서 쏠림이 나왔다

## 고르지 않는 때

- 등록자·승인자 컬럼이 없다

## 추출 로직

1. 유형 ① 조건 등록자 = 조건 승인자
2. 유형 ② 지급 등록자 = 지급 승인자
3. 유형 ③ 조건 등록자 = 지급 처리자
4. 법인·담당자별 건수와 금액

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 소규모 법인의 대결재(위임 규정이 있으면 뺀다)

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 대결재 규정이 있는 법인은 규정 밖 건만 남긴다

## 멈춤 기준

- [DP-018](okf/wiki/patterns/perspective/DP-018.md) 쏠림과 겹치면 실사로 넘긴다

## 함께 쓰기

- [DP-018](okf/wiki/patterns/perspective/DP-018.md), [DP-016](okf/wiki/patterns/perspective/DP-016.md)

## 질문 단서

> 직전 결과의 지급 가운데 컨디션 등록자와 승인자, 지급 등록자와 승인자, 컨디션 등록자와 지급 처리자가 같은 건을 뽑아 담당자 코드별로 보여 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPF063`(컨디션 헤더: 승인정보), `TI_GRPF060`(지급 헤더)

## 확인 필요

- 컨디션·지급의 등록자·승인자 컬럼
