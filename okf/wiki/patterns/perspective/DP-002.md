# DP-002 정산 단위 재집계

- 묶음: **진위 판별** — 대사로 나온 초과가 진짜 초과인지, 기준·단위·표기 문제로 생긴 초과인지 가른다
- 관점: 정산 단위 — 최소 단위의 초과가 상위 단위로 묶어도 초과인가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (상위 단위에서도 초과면 ④)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 정산 기준은 최소 단위(SKU)인데 업무 편의상 상위 단위(모델·마케팅명)로 일괄 정산하면, 대표 단위에는 초과가 생기고 나머지 단위에는 지급이 비어 보인다. 상위 단위로 다시 집계하여 이런 표기상 초과를 걷어낸다.
- 답하는 질문: 최소 단위에서 초과인 건이 같은 상위 단위의 형제 단위까지 합하면 해소되는가
- 관련 패턴(참고): [P-102 테이블간 조인 불일치](okf/wiki/patterns/anomaly/P-102.md), [P-130 집중도 이상](okf/wiki/patterns/anomaly/P-130.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 결과의 초과 KEY 가 같은 상위 단위(모델) 안의 특정 제품 하나에 몰리고, 형제 제품은 공급만 있고 지급이 없다
- 초과 KEY 가 출시 초기 제품에 많다
- 보고서나 법인 업무 설명에 모델·마케팅명 단위 정산이 언급된다

## 고르지 않는 때

- 제품 마스터에 최소 단위 → 상위 단위 매핑이 없다(문자열 자르기로 대신하지 않는다) → 확인 필요로 남긴다
- 결과의 제품이 대부분 상위 단위에 하나뿐이다

## 추출 로직

1. 직전 결과의 KEY 에 마스터 기준 상위 단위(모델코드)를 붙인다. 마스터에 없는 제품은 「상위 단위 미확인」으로 분리한다
2. 같은 법인·거래선·상위 단위에 속한 모든 형제 제품의 누적 공급·지급을 [DP-001](okf/wiki/patterns/perspective/DP-001.md) 과 같은 규칙으로 산출해 상위 단위로 합산한다
3. 판정 ① 해소: Σ공급 ≥ Σ지급 → 「정산 단위 혼용」. 과지급이 아니므로 결과에서 뺀다
4. 판정 ② 유지: Σ공급 < Σ지급 → 「과다청구 후보」. 결과에 남긴다
5. 상위 단위 초과 금액은 평균 단가 대신 초과가 난 제품의 단가를 그대로 쓴다(색상·용량별 단가 차이 때문)

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 후속 모델·파생 모델(같은 마케팅명, 다른 모델코드)을 한 단위로 묶으면 초과가 가려진다 → 모델코드 기준을 지킨다
- 번들 구성품은 본품과 제품 코드가 다르다 → 본품 기준으로 맞춘다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 해소 판정의 허용 범위는 단가 반올림 수준으로만 둔다

## 멈춤 기준

- 초과가 대부분 ①로 해소되면 「정산 단위 혼용 법인·모델 목록」으로 정리하고 통제 미흡 시나리오로 멈출 수 있다
- ② 가 남으면 그 KEY 만 남기고 다음 드릴다운으로 간다

## 질문 단서

> 직전 결과의 초과 건을 같은 거래선·모델 단위로 다시 묶어, 형제 SKU 의 공급까지 합해도 지급이 공급을 넘는 건만 남겨 줘. 모델로 묶으면 해소되는 건은 정산 단위 혼용으로 따로 표시해 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- Risk 사례: ■■법인 정산 담당자가 런칭 초 모델 단위(다수 SKU 를 대표 1개 SKU 로 정산) → 이후 SKU 단위로 정산, 대표 SKU 에서 과지급 이상징후 발생(색상별 5개 SKU 를 1개 SKU 로 정산)
- GPPM 상 셀아웃 프로모션 정산 기준은 SKU
- 관련 테이블: `TI_GRPF061`(지급 항목, 자재번호 `MATNR`), `TI_GRPF064`(컨디션 항목, 제품별 조건수량), `TI_GRPF066`(컨디션 시나리오, 제품 `ARTNR`), `TI_GRPB004B`(빌링)

## 확인 필요

- SKU ↔ 모델 매핑 마스터(GSCM 법인/SKU별 마스터)의 테이블·컬럼
