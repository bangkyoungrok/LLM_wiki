# DP-006 지급수량 3자 대조

- 묶음: **진위 판별** — 대사로 나온 초과가 진짜 초과인지, 기준·단위·표기 문제로 생긴 초과인지 가른다
- 관점: 수량 신뢰성 — 시스템의 지급수량이 실제 정산수량인가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (세 수량이 맞는데 초과면 ④)
- 대상 범위: **좁힘** — 직전 결과 안에서 조건을 더해 줄인다
- 설명: 수작업 정산 법인은 시스템 지급수량에 충당수량(계획수량)이나 공급수량이 그대로 남아 있을 수 있다. 그러면 수량은 과다 표기, 금액은 실제 정산 기준이 되어 초과처럼 보인다. 지급수량을 계획·검증·역산 수량과 대조해 표기상 초과를 가른다.
- 답하는 질문: 지급 항목의 수량이 계획수량·검증수량·금액 역산수량과 맞는가
- 관련 패턴(참고): [P-101 필드간 값 불일치](okf/wiki/patterns/anomaly/P-101.md), [P-102 테이블간 조인 불일치](okf/wiki/patterns/anomaly/P-102.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 초과가 특정 법인에 몰리고, 그 법인의 지급수량이 계획수량과 자주 똑같다
- 지급 금액은 평소 수준인데 지급수량만 크다(역산 단가가 비정상적으로 낮다)
- 보고서에 법인이 금액 기준으로만 관리한다거나 수작업 검증이 언급된다

## 고르지 않는 때

- 지급 조건이 수량 구간별 단가(Tier)이거나 정액 지원이라 역산이 맞지 않는다

## 추출 로직

1. 지급 항목마다 ⓐ 계획수량(컨디션 항목의 프로모션 수량) ⓑ 검증수량(셀아웃 검증 정산 내역의 인정 수량) ⓒ 역산수량(지급 금액 / 조건 단가, 같은 통화)을 붙인다
2. 판정 ① 충당수량 방치: 지급수량 = ⓐ 이고 ⓒ < 지급수량 → 「수량 과다집계」. 보정 지급수량 = ⓒ
3. 판정 ② 공급수량 고정: 지급수량 = 같은 기간·제품의 공급수량이고 지급이 원빌링을 참조한 빌링 정정 형태 → 「예외 프로세스」
4. 판정 ③ 실제 초과: 지급수량·ⓑ·ⓒ 가 서로 맞고 보정 후에도 KEY 초과가 유지 → 결과에 남긴다
5. 법인별로 ①② 비중을 내고, 비중이 높은 법인은 「수량 관리 미흡 법인」으로 표시한다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 현지 세법상 매출차감 대신 공급 인보이스를 수정 발행하는 법인 — 시스템 수량이 공급수량으로 고정된다. 실정산 수량은 법인 자체 시스템에 있다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 일치 판단의 허용 오차는 단가 반올림 범위로 둔다
- ①② 비중이 높은 법인은 수량 대사 대신 금액 기준 대사로 바꿔 다시 본다

## 멈춤 기준

- 초과가 대부분 ①② 로 해소되면 「수량 관리 미흡 법인 목록」으로 정리하고 멈출 수 있다
- ③ 만 남기고 다음 드릴다운으로 간다

## 함께 쓰기

- [DP-007](okf/wiki/patterns/perspective/DP-007.md) — 같은 지급 항목에서 검증 절차까지 함께 볼 때

## 질문 단서

> 직전 결과의 지급 항목마다 지급수량을 컨디션 계획수량, 셀아웃 검증 인정수량, 지급 금액을 조건 단가로 나눈 수량과 비교해, 충당수량이 그대로 남은 건과 공급수량으로 고정된 건을 빼고 세 수량이 맞는 초과 건만 남겨 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- Risk 사례: ■■법인은 수작업 수량 검증 중 시스템 정산수량이 충당수량으로 입력되었으나 실정산수량으로 고치지 않고 방치(수량 참조값이 없으면 충당수량 반영, 법인은 금액 기준으로만 관리)
- Risk 사례: ■■법인은 현지 세법상 매출차감 대신 셀인 인보이스를 수정 발행, 시스템 정산수량이 셀인수량으로 과표기(인보이스 금액만 차감)
- 관련 테이블: `TI_GRPF061`(지급 항목: `PYDOC`, `PITEM`, `PRICE`, `TCAMT`, `IVAMT`), `TI_GRPF064`(컨디션 항목: `CODOC`, `CITEM`, 프로모션 수량), `TI_GRPB_DE_SELLOUT`, `TI_GRPB004B`(원빌링 `ORG_SO`)

## 확인 필요

- 지급 항목의 수량 컬럼명
- 컨디션 항목의 조건 단가·프로모션 수량 컬럼명
- `TI_GRPB_DE_SELLOUT` 의 1행 단위와 인정 수량 컬럼
- Tier 단가·정액 지원 구분 컬럼
