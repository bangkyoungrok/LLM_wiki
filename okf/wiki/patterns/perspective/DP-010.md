# DP-010 기간 겹침 중복 지급

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 중복 — 판매기간이 겹치는 가격성 할인을 둘 다 지급했는가
- 사고 유형: ④ 검증부실/과다지급 (중복 청구)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 가격성 할인은 한 대당 중복 지급이 불가능하다. 누적 대사는 기간이 겹치는 조건 가운데 수량이 최대인 조합만 세고 나머지를 계산에서 빼지만, 빠진 조건에도 실제 지급이 있었다면 그 지급 자체가 중복 지급 의심이다. 직전 결과의 거래선·제품 안에서 판매기간이 겹치는 지급 조건 쌍을 찾는다.
- 답하는 질문: 직전 결과의 거래선·제품에서 판매기간이 겹치는 가격성 할인 조건이 둘 이상 지급되었는가
- 관련 패턴(참고): [P-122 완전 중복](okf/wiki/patterns/anomaly/P-122.md), [P-117 식별자 중복](okf/wiki/patterns/anomaly/P-117.md), [P-004 영수증/송장 위조 및 중복 청구](okf/wiki/patterns/fraud/P-004.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 직전 계산이 기간 겹침 조건을 빼고 셌다([DP-001](okf/wiki/patterns/perspective/DP-001.md) 방식)
- 결과 안에 같은 거래선·제품에 동시 진행 프로모션이 많다

## 고르지 않는 때

- 대상 프로모션 유형이 중복 적용 허용 유형이다

## 추출 로직

1. 같은 KEY 의 가격성 할인 지급 조건끼리 판매기간이 하루 이상 겹치는 쌍을 찾는다
2. 겹침 구간 수량 = 조건 지급수량 × (겹친 일수 / 조건 판매기간 일수). 중복 의심 수량 = 두 조건의 겹침 구간 수량 중 작은 값
3. 금액 = 중복 의심 수량 × 두 조건 중 낮은 지급 단가(보수적 산출)
4. 직전 결과의 KEY 가운데 누적 대사 계산에서 빠졌는데 지급된 조건의 지급액 합계를 따로 낸다
5. 유형 교차: 같은 KEY·기간에 중복 불가인 다른 가격성 유형(B2B 특가 등)이 함께 지급된 건도 같은 방식으로 본다
6. 확정도 「상」 = 겹친 구간의 지급수량 합 > 같은 구간 종료일의 판매가능수량([DP-008](okf/wiki/patterns/perspective/DP-008.md))

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 같은 프로모션을 월 단위로 나눠 등록한 것은 이어진 기간이지 겹친 기간이 아니다
- 한 조건의 분할 지급은 중복이 아니다(한도는 [DP-014](okf/wiki/patterns/perspective/DP-014.md) 에서 본다)
- 취소·역분개된 지급, 부호가 반대인 같은 금액 쌍은 뺀다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 겹침 쌍이 많으면 같은 거래선에서 여러 분기 반복된 쌍으로 올린다
- 일수 비례는 추정이므로 확정도 「상」을 먼저 둔다

## 멈춤 기준

- 같은 거래선에서 여러 분기 반복되면 멈출 수 있다
- 확정은 거래선의 일자별 판매 명세로 한다

## 질문 단서

> 직전 결과의 거래선·SKU 가운데 판매기간이 겹치는 가격성 할인 컨디션이 둘 다 지급된 건만 남기고, 겹친 일수로 중복 의심 수량과 금액을 계산해 줘. 누적 대사에서 빠졌는데 지급된 컨디션은 따로 표시해 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 제공 원본 참고사항: 판매 법인은 동일 SKU 에 중복 프로모션이 가능하나 B2B 특가/가격성 할인은 중복 불가
- 제공 원본 사고 발생 원인: 동일 판매실적을 여러 행사에 반복 제출, 프로모션 간 통합 검증 미실시
- 관련 테이블: `TI_GRPF063`(컨디션 헤더: 계약기간, 인센티브 유형), `TI_GRPF066`(컨디션 시나리오: 활동 상세), `TI_GRPF060·061`(지급: 상태)

## 확인 필요

- 가격성 할인으로 볼 Activity·인센티브 유형 코드 목록(O110 外)
- 지급 상태 코드(취소·역분개)
