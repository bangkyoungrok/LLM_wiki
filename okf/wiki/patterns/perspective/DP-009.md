# DP-009 공급 전 청구

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 순서 — 공급보다 실적 청구가 먼저인가
- 사고 유형: ④ 검증부실/과다지급 (같은 거래선에 반복되면 ⑥)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 판매실적은 공급받은 물량을 판 뒤에 생긴다. 지급 조건의 판매기간이 그 거래선·제품의 첫 공급보다 앞서면 실적 없는 청구다. 직전 결과의 지급 가운데 판매기간이 공급보다 앞선 건을 찾는다.
- 답하는 질문: 직전 결과의 지급 가운데 판매기간이 첫 공급보다 앞선 건이 있는가
- 관련 패턴(참고): [P-111 선후 순서 위반](okf/wiki/patterns/anomaly/P-111.md), [P-113 비정상 단축](okf/wiki/patterns/anomaly/P-113.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 직전 결과의 KEY 가운데 최초 공급일이 늦은(출시 초기, 신규 거래선) KEY 가 있다
- 결과 안에 판매기간 종료 직후 큰 공급이 들어온 KEY 가 보인다

## 고르지 않는 때

- [DP-005](okf/wiki/patterns/perspective/DP-005.md) 에서 간접 공급으로 판정된 거래선 — 직접 공급이 늦거나 없어 모두 공급 전 청구로 잡힌다

## 추출 로직

1. 지급 조건마다 판매기간 시작·종료일과 해당 KEY 의 최초 공급일을 붙인다
2. 유형 ① 전체 선행: 판매기간 종료일 < 최초 공급일. 지급 전액이 실적 없는 지급
3. 유형 ② 일부 선행: 판매기간 시작일 < 최초 공급일 ≤ 판매기간 종료일. 공급 전 일수 비율만큼을 의심 수량으로 낸다
4. 거래선별 ①② 반복 횟수와 분기 수를 낸다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 운송 중 재고 — 판매기간 종료일과 공급일 차이가 통상 리드타임 안이면 뺀다
- 사전 예약 판매처럼 공급 전 판매가 승인된 프로모션

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 리드타임 기준은 법인·제품군별 공급일 ~ 판매기간 종료일 간격 분포를 보고 정한다

## 멈춤 기준

- ① 은 건 자체가 실적 없는 지급이므로 멈출 수 있다
- 같은 거래선에 여러 분기 반복되면 ⑥ 유형으로 보고 멈춘다

## 함께 쓰기

- [DP-008](okf/wiki/patterns/perspective/DP-008.md) — 같은 KEY·지급 문서에서 시점 관점을 함께 볼 때

## 질문 단서

> 직전 결과의 셀아웃 인센티브 지급 가운데 컨디션 판매기간이 그 거래선·SKU 의 첫 셀인보다 앞선 건을 뽑고, 판매기간 전체가 앞선 건과 일부만 앞선 건을 나눠 의심 수량과 금액을 보여 줘. 통상 리드타임 안의 차이는 제외해 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPB004B`(빌링: `BILL_DT`), `TI_GRPF063`(컨디션 헤더: 계약기간), `TI_GRPF060·061`(지급)

## 확인 필요

- 컨디션 판매기간 컬럼
- 법인·제품군별 통상 리드타임
