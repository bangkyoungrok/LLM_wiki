# DP-016 승인 전 지급

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 승인 — 지급 조건 승인 전에 지급했는가
- 사고 유형: ⑦ 정책/시스템 통제 미흡 (승인 우회)
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 지급은 승인된 조건에 대해서만 이뤄져야 한다. 지급일이 조건 승인일보다 앞서거나, 승인 정보가 비어 있는 조건으로 지급된 건을 찾는다.
- 답하는 질문: 지급일이 조건 승인일보다 늦고, 승인 정보가 있는가
- 관련 패턴(참고): [P-111 선후 순서 위반](okf/wiki/patterns/anomaly/P-111.md), [P-123 필수 필드 NULL](okf/wiki/patterns/anomaly/P-123.md), [P-008 시스템 제어 우회](okf/wiki/patterns/fraud/P-008.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 결과의 조건 일부에 승인 정보가 비어 있다
- [DP-015](okf/wiki/patterns/perspective/DP-015.md) 결과와 겹치는 조건이 있다

## 고르지 않는 때

- 승인 정보 컬럼이 없다

## 추출 로직

1. 유형 ① 승인 전 지급: 지급일 < 조건 승인일
2. 유형 ② 승인 없음: 승인일·승인자가 비어 있는 조건의 지급
3. 법인·담당자별 건수와 금액

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 시스템 이관 등으로 과거 조건의 승인 정보가 비어 있는 기간 — 기간으로 뺀다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 같은 날 승인·지급은 처리 순서 문제일 수 있다 → 날짜가 다를 때만 본다

## 멈춤 기준

- 건 자체가 통제 위반이므로 금액이 유의하면 멈출 수 있다

## 질문 단서

> 직전 결과의 지급 가운데 컨디션 승인일보다 먼저 지급되었거나 승인 정보가 없는 컨디션으로 지급된 건을 뽑아 법인·담당자별로 보여 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPF063`(컨디션 헤더: 승인정보), `TI_GRPF060`(지급 헤더)

## 확인 필요

- 컨디션 승인일·승인자 컬럼
- 지급일 컬럼
