# DP-011 증빙·내역 중복 지급

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 중복 — 같은 증빙·같은 판매 건으로 두 번 지급했는가
- 사고 유형: ④ 검증부실/과다지급 (중복 증빙)
- 대상 범위: **좁힘** — 직전 결과 안에서 조건을 더해 줄인다
- 설명: 직전 결과의 지급 가운데 같은 청구 증빙(청구문서)이 서로 다른 지급 문서에 쓰였거나, 같은 거래선·제품·수량·단가·금액의 지급이 반복되었거나, 같은 판매 건이 여러 정산에 들어간 이중 지급을 찾는다.
- 답하는 질문: 직전 결과의 지급 가운데 같은 증빙이나 같은 판매 건이 둘 이상의 지급에 쓰였는가
- 관련 패턴(참고): [P-119 증빙 중복](okf/wiki/patterns/anomaly/P-119.md), [P-122 완전 중복](okf/wiki/patterns/anomaly/P-122.md), [P-117 식별자 중복](okf/wiki/patterns/anomaly/P-117.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 결과 안에 같은 수량·금액의 지급이 반복된다
- 보고서에 증빙 관리가 지급 조건 단위로만 된다는 언급이 있다

## 고르지 않는 때

- 지급 항목에 청구문서·증빙 번호가 없다 → ③ 동일 내역 반복만 본다

## 추출 로직

1. 유형 ① 증빙 중복: 같은 청구문서가 서로 다른 지급 문서에 2회 이상 연결
2. 유형 ② 동일 내역 반복: 같은 거래선·제품·수량·단가·금액의 지급 항목이 서로 다른 지급 문서로 반복
3. 유형 ③ 판매 건 중복: 셀아웃 검증 정산 내역의 같은 판매 건이 여러 정산에 포함
4. 지급 Activity 의 속성·값에 증빙번호가 있으면 같은 기준으로 확인한다
5. 취소·재처리 쌍(취소 상태, 부호가 반대인 같은 금액)을 먼저 걷어낸다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 정기 고정 지원처럼 같은 금액이 매월 반복되는 정상 지급 — 지급 조건이 다르면 판매기간이 이어지는지 본다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- ② 는 오탐이 많다 → 판매기간까지 같은 건으로 올린다

## 멈춤 기준

- ①③ 은 건 자체가 이중 지급이므로 바로 멈춘다

## 함께 쓰기

- [DP-010](okf/wiki/patterns/perspective/DP-010.md) — 함께 쓰면 「중복」 관점을 한 번에 끝낸다

## 질문 단서

> 직전 결과의 지급 가운데 같은 청구문서가 서로 다른 지급 문서에 두 번 이상 쓰인 건, 같은 거래선·SKU·수량·단가·금액의 지급이 반복된 건, 같은 판매 건이 여러 정산에 들어간 건을 취소·재처리를 뺀 뒤 뽑아 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 관련 테이블: `TI_GRPF061`(지급 항목: 청구문서 `VBELN`, `PYDOC`, `PITEM`), `TI_GRPF062`(지급 Activity: `FNAME`, `VALUE`), `TI_GRPB_DE_SELLOUT`

## 확인 필요

- 지급 상태 코드(취소·역분개)
- 셀아웃 검증 내역에 판매 건을 식별할 컬럼(판매일·판매점·시리얼)이 있는지
