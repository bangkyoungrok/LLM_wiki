# DP-012 반품 후 수량차감 누락

- 묶음: **수법 특정** — 남은 초과가 어떤 수법(시점·중복·반품·조건)으로 생겼는지 특정한다
- 관점: 반품 — 인센티브를 받은 물량이 반품됐는데 차감했는가
- 사고 유형: ④ 검증부실/과다지급
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 누적 대사는 반품을 누계에서 빼기만 한다. 인센티브를 이미 받은 물량이 나중에 반품되면 소비자에게 팔리지 않았다는 뜻이므로 수량차감이 뒤따라야 한다. 반품 시점의 '아직 인센티브를 받지 않은 재고'를 넘는 반품을 찾아 차감 여부를 대조한다.
- 답하는 질문: 인센티브 지급 뒤 반품이 있었는데 그만큼 수량차감이 되었는가
- 관련 패턴(참고): [P-102 테이블간 조인 불일치](okf/wiki/patterns/anomaly/P-102.md), [P-111 선후 순서 위반](okf/wiki/patterns/anomaly/P-111.md), [P-030 고객 환불 부정](okf/wiki/patterns/fraud/P-030.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 결과 안의 KEY 에 지급 이후 반품·취소가 있다
- 보고서의 초과 KEY 가 반품이 많은 제품에 몰린다

## 고르지 않는 때

- 반품이 대부분 소비자 반품(판매 후 반품)이고 프로모션 규정상 인센티브가 유지된다

## 추출 로직

1. 반품·취소 = 반품, 매출 취소. 반품 취소는 상계한다. 원빌링 정보로 원래 공급 건과 연결한다
2. 미청구 재고(반품 직전) = 누적 공급 − 누적 지급수량
3. 필요 차감 수량 = 반품수량 − 미청구 재고(양수만)
4. 미차감 수량 = 필요 차감 수량 − 반품일 이후 실제 수량차감(양수만). 금액 = 미차감 수량 × 반품 직전 최근 지급 단가
5. 지급 직후 반품: 판매기간 종료일(또는 지급일)과 반품일 간격, 반품수량 / 직전 지급수량을 함께 표시한다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 소비자 반품 — 반품 사유로 구분한다
- 불량 교환으로 같은 제품이 재출고된 경우 — 반품과 재출고를 상계한다
- 재고보상(가격 인하분 보전)은 셀아웃 인센티브가 아니다 — 유형을 한정한다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- '지급 직후'·'큰 비중'의 기준은 간격·비중 분포를 보고 정한다

## 멈춤 기준

- 미차감 금액이 유의하면 회입 대상으로 멈춘다

## 함께 쓰기

- [DP-013](okf/wiki/patterns/perspective/DP-013.md) — 반품이 기간 말 공급분에 몰렸는지 함께 볼 때

## 질문 단서

> 직전 결과의 거래선·SKU 마다 인센티브 지급 이후 반품을 찾고, 반품 시점에 아직 인센티브를 받지 않은 재고를 넘는 반품 수량만큼 수량차감(DR)이 없었던 건과 미차감 금액을 뽑아 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 기준 시나리오: 셀아웃 인센티브 과다지급(영업 / 판매법인 / 매출차감, '23.上 등록). 거래선/SKU 기준 누적 셀인 < 셀아웃 인센티브 지급수량
- 제공 원본 점검시나리오: 실제 판매/취소/반품 내역을 추가 비교하여 미판매 물량 청구를 선별
- 관련 테이블: `TI_GRPB004B`(빌링: `BILL_DT`, `ORG_SO`, `ORG_BILL_DT`, 빌링타입), `TI_GRPF060·061`(지급, DR)

## 확인 필요

- 수량차감(DR) 식별 컬럼·값
- 반품 사유 코드 컬럼
- 빌링타입 컬럼명
