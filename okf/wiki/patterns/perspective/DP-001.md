# DP-001 누적 공급량 대사

- 묶음: **기준 대사** — 직전 결과에 대사 기준 자체가 없을 때 누적 대사를 세운다
- 관점: 누적 수량 — 공급받은 것보다 많이 청구했는가
- 사고 유형: ④ 검증부실/과다지급
- 대상 범위: **대조** — 직전 결과를 다른 테이블과 맞대어 남길 건과 뺄 건을 가른다
- 설명: 실적에 따라 지급하는 비용(인센티브·리베이트·장려금)의 누적 지급수량을, 같은 대상에 실제로 공급한 누적 수량과 대조하여 공급량을 넘는 지급을 찾는다. 청구서 한 건씩 검증해서는 드러나지 않는 누적 초과를 잡는다.
- 답하는 질문: 같은 거래선·제품에 최초 공급부터 누적한 공급량보다 누적 지급수량이 많은가
- 관련 패턴(참고): [P-001 인센티브 조작](okf/wiki/patterns/fraud/P-001.md), [P-108 누적 임계 초과](okf/wiki/patterns/anomaly/P-108.md), [P-102 테이블간 조인 불일치](okf/wiki/patterns/anomaly/P-102.md)

## 고르는 때

보고서(누적 보고서와 부록 SQL)에서 아래 신호가 보이면 이 패턴을 후보로 둔다.

- 직전 결과가 실적 기반 지급 건인데, 직전 SQL 에 지급 수량을 공급·출고 기록과 대조하는 조건이 없다
- 결과 안에 같은 거래선·제품으로 여러 프로모션·여러 차례 지급이 반복된다
- 보고서가 개별 청구서·프로모션 단위 검증만 언급하고 누적 검증은 언급하지 않는다

## 고르지 않는 때

- 직전 SQL 에 이미 누적 공급량 대사가 있다 → 진위 판별([DP-002](okf/wiki/patterns/perspective/DP-002.md) ~ [DP-007](okf/wiki/patterns/perspective/DP-007.md))로 간다
- 지급이 수량과 무관한 정액 지원이다

## 추출 로직

1. 점검 KEY = 법인 + 거래선 + 제품(정산 최소 단위). 공급 쪽 거래선(주문처)과 지급 쪽 거래선(지급 고객)은 매핑 기준으로 묶고, 기준이 없으면 1:1 로 본다
2. 누적 공급량 = 최초 공급일부터 누적. 매출은 양수, 매출 취소·반품은 음수, 반품 취소는 양수로 반영한다. 점검 기간으로 자르지 않는다
3. 누적 지급수량 = 중복 지급이 불가능한 유형(가격성 할인)만, 수량차감 제외. 판매기간이 겹치는 지급 조건은 기간이 겹치지 않는 조합 가운데 수량 합계가 최대인 조합으로 고른다(같은 수량이면 금액이 큰 조건)
4. 초과수량 = 누적 지급수량 − 누적 공급량(양수만). 초과 금액 = 초과수량 × 지급 단가(선정된 지급금액 합 / 선정 수량 합)
5. 누적 공급·지급이 0 이하인 KEY 는 뺀다

## 정상 예외

질문에 「제외해 줘」로 넣는다.

- 기간 초에 이미 보유하던 재고를 판매한 경우 — 같은 기간끼리 비교하지 않고 최초 공급부터 누적해 비교한다
- 한 제품에 중복 적용이 허용된 프로모션 유형 — 가격성 할인으로 한정한다
- 단종·구형 제품(마스터 기준 출시 시점 이전) — 대상에서 뺀다

## 임계 조정

숫자를 새로 정하지 않는다. 기준은 시나리오 생성 에이전트가 데이터 분포를 보고 정한다.

- 초과 KEY 가 결과의 대부분을 차지하면 초과수량이 아니라 초과 비율(초과수량 / 누적 공급량)이 분포 상위인 KEY 로 올린다
- 초과 금액이 작은 KEY 가 많으면 금액 하한을 두되, 값은 초과 금액 분포를 보고 정한다

## 멈춤 기준

- 초과 KEY 가 소수로 모이고 진위 판별(A 묶음)이 이미 끝났으면 멈춘다
- 진위 판별을 하지 않았으면 멈추지 않는다. 초과에 정산 단위·거래선 기준·수량 표기 문제가 섞여 있기 때문이다

## 질문 단서

> 직전 결과의 지급 건 가운데, 같은 거래선·제품으로 최초 공급부터 누적한 공급량보다 누적 지급수량이 많은 건으로 좁혀 줘. 기간이 겹치는 가격성 할인은 겹치지 않는 조합 중 수량이 가장 큰 것만 세어 줘.

드릴다운 질문의 「이번 관점」 줄로 쓴다(원본 질의와 이전 관점 줄 뒤). 직전 결과에 맞춰 고쳐 쓰고, 함께 고른 패턴이 있으면 한 줄로 합친다. 물리명·패턴 번호는 쓰지 않는다.

## 대입 예시: 셀아웃 인센티브 과다지급

- 이 패턴은 기준 시나리오의 1단계 로직을 일반화한 것이다
- 셀인 = N-ERP 빌링수량(`TI_GRPB004B`). 양수: 일반 매출(YN01·YN02), 번들 매출(YNB1), 리뎀션(YNB2), 반품 취소(YRC1) / 음수: 일반 매출 취소(YNC1), 번들 매출 취소(YNBC), 반품(YR01·YR02·YR03), RT
- 셀아웃 = N-ERP 인센티브 지급수량, SPOT 프로모션의 Direct Price Discount(Activity O110)만, 수량차감(DR) 제외
- 거래선 = 셀인 Sold-to / 셀아웃 Customer 를 GSCM Site Group(`TI_GRPB_CUSTOMER_MAPPING`)으로 매핑, 없으면 Sold-to 1:1. 유통구분 목적 그룹(Other, Online 등)은 제외
- 금액 = (셀아웃 수량 − 셀인 수량) × 단가, 단가 = 셀아웃 Invoice 금액(USD) 합계 / 선정된 매출차감수량 합(DR 제외)
- 대상 = MX(휴대폰·태블릿), VD(TV·모니터), DA(냉장고·세탁기·에어컨·MWO). '17년 이전 모델 제외
- 사고사례 4건, 231억원(1,662만불, 1,400원/$ 기준)

## 확인 필요

- 누적 지급수량을 구하는 지급 항목의 수량 컬럼명
- 컨디션 판매기간 시작·종료 컬럼
