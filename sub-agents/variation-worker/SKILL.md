# variation-worker

## 맡는 일

위임 prompt 로 넘겨받은 변형 후보 1건만 분석 기간 데이터로 확인한다. 변형을 다시 설계하지 않고, 넘겨받은 대응표와 조각의 뜻을 지키면서 **정해진 질의 순서와 상한 안에서** 세 가지를 확인한다: 변형 조건이 조건 단위로 재현되는지(찬성 근거), 정상 업무나 데이터 특성으로 설명되지 않는지(반대 근거), 시나리오 SQL 로 쓸 수 있는지.

## 상한 (이 subagent 전체)

| 항목 | 상한 |
|---|---|
| `sql_run` | **5회** (질의 ① 1회 + 경로 최대 2회 + 질의 ② 1회 + 오류 수정 1회) |
| 통계 도구(`stat_screen`, `find_duplicates`, `find_number_gaps`, `match_tables`) | 2회. 통계 경계가 필요한 조각(위임 prompt 8항)에만 쓴다 |
| 도구를 부르는 응답 | 10회 |

- 위임 prompt 의 「확인된 사실」(날짜 형식, 코드값, 업무 키, PII, 조인, 정상 조건)은 다시 확인하지 않는다. 값 확인 질의, 조인 실측, 표본 조회를 따로 실행하지 않는다. 확인된 사실에 없는 값이 꼭 필요하면 경로 1회를 그 확인에 쓰고, 가능하면 질의 ① 안에 열로 함께 넣는다.
- 같은 SQL 은 다시 실행하지 않는다. 오류 수정은 전체 1회뿐이다. 수정 뒤에도 오류면 보류(이유: 실행 오류 <오류 문구>)로 끝낸다.
- 상한에 닿으면 더 부르지 않고, 그때까지의 결과로 판정한다(충분성을 못 채웠으면 보류, 이유: 호출 상한).

## 절차

1. 읽기(한 응답): `skill_view` 로 `sql-query` 를 읽고, 같은 응답에서 `skills/scenario-variation/references/query-writing.md`, 위임 prompt 의 패턴 page·분류 파일, 대상 테이블 문서를 `agent_studio_project_view` 로 함께 읽는다. 통계 경계가 필요한 조각이 있을 때만 `skills/scenario-variation/references/stat-views.md` 와 `result-reading.md` 도, 위임 prompt 에 정상 조건이 없을 때만 `wiki/normal-patterns.md` 도 함께 읽는다.
2. 질의 계획: 질의 ①, 경로(쓸 때만), 질의 ②의 SQL 을 먼저 정하고 상한 안에 드는지 확인한다. 조각은 위임 prompt 의 초안을 테이블 문서 컬럼과 대조해 다듬되, 조각의 뜻과 대응표를 바꾸지 않는다.
3. 통계 경계(필요할 때만, 통계 도구 최대 2회): 조각이 「평소 범위」·「동료 대비」 같은 통계 경계를 요구하면 `stat-views.md` 의 인자로 도구를 부르고, 돌려받은 `boundaries` 값을 그대로 조각의 리터럴로 쓴다. 범위 밖 후보가 0 이면 그 조각은 신호가 없는 것이므로 조각을 빼고(경로 「조각 수정」) 계속한다.
4. 질의 ① 변형 검증 질의(필수, `sql_run` 1회): `query-writing.md` 6절의 질의로 비교 지표(`TARGET_VAL`, `BASE_VAL`), 변형 재현(`HIT_KEY_CNT`), 조각별 단독 건수(`A_CNT`, `B_CNT`), 반례(`NORMAL_CNT`)를 한 번에 본다. 비교 지표는 위임 prompt 7항의 정의대로 계산한다. 6절 판단 표로 처리한다.
5. 경로(필요할 때만, 최대 2회): 아래 경로 표에서 고른다. 질의 ①로 충분성 1~3을 이미 채웠으면 경로를 쓰지 않고 6단계로 간다.
6. 질의 ② 건수 점검(필수, `sql_run` 1회): 변형 예외 질의와 모집단 질의를 `query-writing.md` 2절 규칙(한 줄, 분석 기간 리터럴, 키 단위 행, 조건 단위, 조각을 6절 유형대로)으로 정리하고, 3절의 건수 점검 질의를 1회 실행해 `AGENTS.md` 7절 표로 판정한다. 통과하면 끝낸다.
7. 반환 형식으로 답한다.

## 경로

| 경로 | 고르는 때 | 하는 일 (각 1회) |
|---|---|---|
| 조각 수정 | 질의 ①에서 `HIT_KEY_CNT` 가 0 이거나 통계 경계 조각의 범위 밖 후보가 0 | 원본에 없던 더한 조각을 빼거나, 바꾼 조각을 원본 조각으로 되돌려 질의 ①을 다시 실행한다. 원본과 같은 SQL 이 되면 반박(이유: 변형 조건에 해당 건 없음) |
| 세분화 조회 | 차이가 일부 기간·품목·사이트에 몰린 것으로 보여 조각을 좁혀야 할 때 | 그 기준으로 나눠 한 번 집계하고, 조각에 조건을 더한다. 더한 조건은 대응표의 뜻을 좁히는 것만 쓴다(새 축을 바꾸지 않는다) |
| 반례 확인 | 위임 prompt 에 정상 조건이 없어 질의 ①에 `NORMAL_CNT` 를 넣지 못했고, 대상 테이블에 정상 설명 후보(계약 시작, 서비스 품목, 정책 할인, 사유 코드, 플레이스홀더)가 있을 때 | 그 정상 설명에 해당하는 변형 건의 비율을 한 번 조회한다 |

- 경로는 합쳐 2회까지다. 다른 테이블로 조인을 넓히는 일은 하지 않는다. 다른 테이블이 필요한 변형은 main agent 가 「흐름→행」 조각으로 넘긴다.

## 충분성 4항목

1. 비교 기준 대비 차이가 있다(`TARGET_VAL` vs `BASE_VAL`, 설계한 방향).
2. 변형 조각을 SQL 조건으로 쓸 수 있다(특정 업체·사원 리터럴 없이).
3. 정상으로 설명되는 경우를 배제했다(`HIT_KEY_CNT - NORMAL_CNT` 가 1 이상, 또는 반례 조건 없음을 적음).
4. 조건 단위로 재현된다(질의 ② 건수 점검 통과).

## 판정

| 결과 | 판정 |
|---|---|
| 충분성 4항목을 모두 충족하고 `HIT_KEY_CNT - NORMAL_CNT` 가 30 이상 | 충분 |
| 충분성 4항목을 모두 충족하고 `HIT_KEY_CNT - NORMAL_CNT` 가 1 ~ 29 | 충분(소수) |
| 비교 기준과 차이가 없음, 변형 조건에 해당 건이 없음, 건수 점검의 예외 0건, 반례가 `wiki/normal-patterns.md` 2절(업무 패턴)로 설명됨 | 반박 |
| 반례가 `wiki/normal-patterns.md` 1절(데이터 특성: 플레이스홀더, 적재 범위, 삭제 잔존, 이력 증폭 등)로 설명됨 | 재분류 |
| 실행 오류가 수정 뒤에도 남음, 호출 상한에 닿음 | 보류 |

## 반환 형식

2,000 token 이하로 아래 순서를 따른다. SQL 은 코드 블록 없이 한 줄 텍스트로 적는다.

1) 판정: 충분, 충분(소수), 반박, 재분류, 보류 가운데 하나와 이유 한 줄
2) 확정한 조각과 대응표: 요소 | 원본 | 변형(확정) | 근거. 조각 수정으로 뺀 조각이나 되돌린 조각이 있으면 그 내용과 이유
3) 예외 질의: 조건 단위 한 줄 SQL(분석 기간 리터럴, 건수 점검을 통과한 글자 그대로. 이 글자가 시나리오 SQL 이 된다)과 key_columns, 금액 컬럼
4) 모집단 질의: 한 줄 SQL
5) 비교 지표: 대상 값, 비교 기준 값과 각각의 뜻(예: 「선정 건 중 최저가가 아닌 업체가 선정된 비율, 변형 대상 테이블 8% / 원본 테이블 3%」)
6) 변형 검증 질의 값: `POP_KEY_CNT`, `HIT_KEY_CNT`, 조각별 단독 건수, `NORMAL_CNT`, 넣은 정상 제외 조건. 통계 경계를 썼으면 도구 이름과 경계 값
7) 건수 점검: POP_CNT, POP_KEY_CNT, HIT_CNT, KEY_CNT, HIT_AMT 와 판정(`AGENTS.md` 7절)
8) 보고서 재료(쉬운 말, 수치 포함, 각 한두 문장)
   - 무엇을 바꿨나: 원본과 달라진 점
   - 이상을 뒷받침하는 근거: 재현된 건수와 비교 기준 대비 차이, 원본 건수와의 비교
   - 정상일 수 있는 이유와 확인 결과: 어떤 정상 설명을 확인했고 몇 건이 해당했는지
9) 부수 발견: 확인 중 드러난 데이터 적재·품질 문제(플레이스홀더, 형식 오류, 빈 값, 중복 적재, 연결 키 없음)와 규모. 없으면 「없음」
10) 호출 수: `sql_run` 몇 회, 통계 도구 몇 회
11) 근거 문서와 남은 가정(자동 생성 문서, 추측 조인, 통계 도구 경계 값 사용 여부, 복원한 원본의 가정)

## 규칙

- 통계 도구의 기간 인자와 SQL 리터럴은 모두 위임 prompt 의 분석 기간을 그대로 쓴다. 기간을 나누거나 바꾸지 않는다.
- 변형의 축과 대응표를 바꾸지 않는다. 조각 수정은 더한 조각을 빼거나 바꾼 조각을 되돌리는 것뿐이다.
- 사용자에게 묻지 않고 다른 agent 에게 일을 맡기지 않는다.
- 중간 질의와 중간 결과, 표본 행의 값은 돌려주지 않는다. PII 컬럼 값을 꺼내지 않는다.
- `sql_submit` 을 부르지 않는다.
