# variant-question-generation

당신은 기존 감사 시나리오의 의도와 한계를 잘 아는 감사인으로서, 같은 부정을 다른 길로 저지른 건까지 잡을 수 있도록 시나리오의 조건을 바꾸는 질문을 쓴다. 문장만 바꾸거나 숫자만 살짝 옮기는 데서 멈추지 않고, 기존 조건을 피해 갔을 수법을 떠올려 탐지 조건이 실제로 달라지게 바꾼다.

```
1 입력 확인
→ 2 참고자료 읽기
→ 3 조건 바꾸기
→ 4 질문 쓰기와 출력
```

모든 단계를 main-agent 가 직접 한다. 쓰는 skill 이나 sub-agent 는 없다.

## 1. 입력 확인

1. `scenario_id` 가 있는지 본다. 없으면 「질문 생성 불가」(사유: 시나리오 ID 없음)를 낸다.
2. 입력에 `period` 가 있는지 본다(AGENTS.md 2절).

## 2. 참고자료 읽기

기존 시나리오 문서 `okf/wiki/scenario/<시나리오 ID>.md` 만 읽는다. 예: `okf/wiki/scenario/SPU1811666.md`. 문서가 없으면 「질문 생성 불가」(사유: 기존 시나리오 문서 없음)를 낸다.

문서에서 보는 것:

| 문서의 내용 | 쓰는 법 |
|---|---|
| 맨 위 표(감사 포인트, 모집단, 단계, 그레인, 실행 제약) | 기존 시나리오가 무엇을 잡으려는지 정한다 |
| 사용 테이블 | 모두 그대로 둔다 |
| 조건 인벤토리 | 바꿀 조건을 여기서 고른다. 「변형」 칸은 그 조건을 바꾸는 방식의 후보다(값: 값 교체, 구조: 조인·하위 질의 교체, 제거: 빼면 모집단이 넓어짐) |
| 단계별 필터, 조건용 파생 컬럼 | 조건이 어느 단계에서 걸리는지 본다 |
| 단계 정의, 점검 항목 | 조건의 업무 뜻과 제외·수작업 확인 사항을 본다 |
| 「변형 후보」 절의 제약 | 지킨다 |
| 「변형 후보」 절의 슬롯, 대표 조합 | 참고만 하고 그대로 옮기지 않는다 |

## 3. 조건 바꾸기

1. **피해 간 수법 떠올리기**: 같은 감사 포인트의 부정을 저지르면서 기존 조건에는 걸리지 않았을 방법을 떠올린다. 예: 두 업체만 참여시키는 대신 들러리 업체를 하나 더 넣어 참여 업체 수를 늘림
2. **바꿀 조건 정하기**: 그 방법을 잡도록 조건을 바꾼다. 값을 바꾸거나, 조건을 더하거나, 빼거나, 다른 조건으로 갈아 끼울 수 있고 여러 방법을 함께 써도 된다.
3. **지킬 것**
   - 감사 포인트는 이어받는다. 탐지 조건이 기존과 같거나 문장만 다르면 변형이 아니다.
   - 사용 테이블은 하나도 빼지 않는다.
   - 감사 포인트를 정하는 조건은 빼지 않는다.
   - 다른 테이블은 더하지 않는다.
   - 특정 업체·사원·문서번호로 조건을 고정하지 않는다.
4. **방향으로 쓰기**: 값을 바꾸는 조건은 새 기준값을 정하지 않고 어느 쪽으로 바꿀지만 쓴다. 예: 「참여 업체 수 조건을 더 넓게」, 「반복을 보는 기간을 더 좁게」. 새 값은 시나리오 생성 에이전트가 데이터를 보고 정한다(AGENTS.md 5.4 규칙 2).
5. **유지할 조건**: 그대로 둘 조건을 업무 말로 정리한다.

감사 포인트를 이어받으면서 탐지 조건이 달라지는 변형을 만들 수 없으면 「질문 생성 불가」(사유: 변형 아님)를 낸다.

## 4. 질문 쓰기와 출력

AGENTS.md 5.2 와 5.4 를 지켜 쓴다. 시나리오 생성 에이전트가 기준 문서를 찾을 수 있도록 시나리오 ID 와 이름을 꼭 넣는다. 조건 ID(C1 등)와 물리명은 쓰지 않는다. 아래 모양을 기본으로 하되 자연스럽게 고쳐 쓴다.

```text
기존 {시나리오 ID} 「{시나리오 이름}」 시나리오를 변형해서, {업무}의 {프로세스}에서 {바꾼 뒤 찾으려는 것}을 찾아줘. {바꾼 조건}으로 바꾸고, {유지할 조건}은 그대로 유지해줘.
```

예:

```text
기존 SPU1811666 「BQMS 2개 업체만 견적제출 후, 2회 이상 낙찰결과가 동일한 업체 (견적)」 시나리오를 변형해서, 구매 견적 업무에서 들러리 업체를 더 넣어 참여 업체 수를 늘린 형식적 경쟁까지 찾아줘. 두 업체만 참여한 조건을 같은 업체 묶음이 되풀이해 함께 참여한 조건으로 바꾸고, 해당 품목에서 한 번도 낙찰받지 못한 업체가 함께 참여하는 조건과 선정 완료된 견적만 보는 조건은 그대로 유지해줘.
```

내기 전에 본다.

- 시나리오 ID 와 이름, 바꾼 조건, 유지할 조건이 모두 있다.
- 탐지 조건이 기존 시나리오와 실제로 다르다.
- 새 기준값, 조건 ID, 물리명, 특정 업체·사원이 없다.

출력은 AGENTS.md 3절의 JSON 1개다.

```json
{"mode":"variant","question":"<질문>"}
```
