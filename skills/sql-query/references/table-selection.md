# 테이블 선택

우선순위 규칙은 `okf/t2s/rules/table-selection.md`(table_type: 종합리포트 > 리포트 > 마스터 > 인터페이스 > 기준정보)를 **항상 읽고** 따른다. 이 문서는 그 규칙을 적용하는 방법이다. 문서만 보고 고른다. 직접 하든 `schema-linker` 가 하든 같은 절차다.

## 1. 후보 모으기

- 질문의 표현(·동의어)이 `okf/glossary/index.md` 의 용어 매핑 표에 있으면, 그 용어를 매핑 표의 `query_name.컬럼` 에 잠그고 비고(오매칭·무컬럼 경고)를 후보 평가에 반영한다. 잠긴 테이블은 후보 목록에 **합류**시켜 2절 유형 순서로 다시 늘어놓는다(우선순위 면제 없음).
- `okf/domains/index.md` 에서 업무에 맞는 도메인 page 를 고른다. 두 업무에 걸치면 2개까지.
- 그 page 「## 테이블 목록」 표에서 아래를 **모두** 후보로 적는다(하나만 고르지 않는다).
  - 설명이 질문의 대상·지표·조건과 맞는 테이블
  - 유형이 「종합리포트」·「리포트」인 테이블 전부(결합 테이블이라 설명이 출처 위주여도 넣는다)
- 도메인 page 로 못 찾은 표현만 OWNER 목차(`okf/schemas/<OWNER>/index.md`)에서 후보를 더한다. 목차 설명으로도 안 잡히면 후보 문서의 `# Schema` 한글명과 값 확인으로 넓혀 본다(3·4절, 그라운딩 판정).
- 뺀다: 「시나리오」 유형, 테이블 문서 링크가 없는 테이블(「(접근 범위 밖)」 등).
- 후보 모으기에 쓰지 않는다: 도메인 page 의 「테이블과 조회 기준」 글, 「관련 업무 지식」, glossary 의 업무 지식, biz-rules (glossary 의 용어 매핑 표는 1절 선단계로 쓴다).

## 2. 순서 정하기

`okf/t2s/rules/table-selection.md` 의 유형 순서로 늘어놓는다. 유형은 도메인 표의 「유형 (table_type)」 칸(빈칸은 유형 없음), OWNER 목차에서 더한 후보는 문서 frontmatter `table_type`. `schema-linker` 가 붙인 「추가 후보」는 기존 후보 뒤에 붙이고 유형 순서로 다시 늘어놓지 않는다.

## 3. 고르기 (앞 순서부터)

- 앞 후보부터 문서를 열어(한 응답에 2~3개) 개념(대상·지표·조건·구분·기간)마다 담는 컬럼이 `# Schema` 에 있는지 본다. 한글명이 글자로 같지 않아도 뜻이 같으면 담는 것이다.
- **모든 개념을 담는 첫 후보를 쓴다.**
- 앞 후보를 건너뛸 이유는 「담지 못하는 개념이 있다」 하나뿐이다(`okf/t2s/rules/table-selection.md` 의 예외는 따른다). 이유가 아닌 것: 범위가 질문보다 넓다, 다음 후보가 더 딱 맞아 보인다, 다음 후보의 한글명이 더 같다.
- 모두 담는 후보가 없으면 가장 많이 담는 앞 후보를 기준으로 하고, 모자란 개념만 다음 후보에서 조인으로 가져온다(`skills/sql-query/references/joins.md`).
- 문서 파일이 없으면(읽기 실패) 「문서 없음」으로 적고 건너뛴다.

## 4. 값 확인은 고른 뒤에

질문의 값(이름·코드·번호)은 고른 테이블에서 확인한다(`skills/sql-query/references/value-linking.md`). 고른 테이블에 그 값이 0건이고 다음 후보에는 있으면 다음 후보로 바꾸고 기록에 적는다.

## 5. 기록

답변 「근거」에 한 줄로 남긴다.

```text
테이블 선택: 후보 <A>(<유형>), <B>(<유형>) / 채택 <X>(<유형>) / 건너뛴 이유: <후보마다 담지 못한 개념 또는 값 0건>
```

## 그라운딩 판정

| 상황 | 처리 |
|---|---|
| 후보 1개 | 그 테이블·컬럼으로 확정 |
| 후보 여럿, 업무 의미 같음 | 위 절차로 하나를 고르고 해석을 답변에 밝힌다 |
| 업무 의미가 다른 후보 2개 이상 | 가장 일반적인 해석으로 제출하고, 답변에서 다른 해석과 구분 기준을 보여 묻는다 |
| 질문 표현이 문서에 그대로 없음 | 용어집과 `# Schema` 한글명을 넓게 보고 같은 뜻의 컬럼으로. 답변에 질문 표현 ↔ 실제 컬럼을 밝힌다 |
| 목차에만 있고 문서 없음 | 쓰지 않는다. 대안이 없으면 「미연결(테이블 문서 없음)」 |
| 후보 없음 | 먼저 OWNER 목차 설명, 후보 `# Schema` 한글명(뜻이 같은 컬럼), 약어·법인명은 용어집(`okf/glossary/index.md`), 값 확인(`skills/sql-query/references/value-linking.md`)으로 찾는다. 이것으로도 못 찾을 때만 「미연결」로 두고 찾은 조건만으로 제출. 답변에서 그 조건을 빼고 조회했다고 밝히고 묻는다 |
