# 답변 형식 (T2S 조회 모드)

## 직전 점검

1. DB 값을 답에 쓰는데 `submit_sql` 을 아직 안 불렀으면 답변을 쓰지 않고 지금 부른다. 단 문서만으로 답하는 질문(아래 「문서만으로 답할 때」)이거나 SQL 을 쓸 수 없으면(후보가 전부 「미연결」·「테이블 문서 없음」·「번들에 없음」) `submit_sql` 없이 확인된 내용(미연결이면 사유)만 답한다.
2. 아래 형식에 맞는지만 본다(조건·이름을 다시 검토하지 않는다).

## DB 값을 답에 쓸 때

```markdown
<첫 문장: 질문에 대한 답. 수치에 단위(통화, 건, %), 날짜는 YYYY-MM-DD>

<필요하면 결과 요약 표 — submit_sql 결과의 값만>

**조회 조건**: 기간 …, 통화 …, 기준 시점 …
**근거**
- 테이블·컬럼: APPADAMSUSER.<테이블>.<컬럼> … (`okf/schemas/APPADAMSUSER/tables/<테이블>.md`)
- 테이블 선택: 후보 … / 채택 … / 건너뛴 이유: …
- 조인: <조인 문서 경로> 또는 `추측 조인(번들 문서 없음): …, 근거=…, 고아율=…%`
**가정**: 해석이 갈린 부분, 기간·상태 기본값, 질문 표현 ↔ 실제 컬럼, wiki 자동 생성 해석
**확인 필요**: (있을 때만) 설명 없음, 코드값 불명, 조인 근거 불충분, VPD·마스킹, 문서와 DB 불일치
**다시 묻기**: (모호·미연결이 있을 때만) 다른 해석과 구분 기준, 빼고 조회한 조건
```

- 숫자는 `submit_sql` 결과(`grid_data`, `total_rows_count`)만 쓴다. 결과에 없는 숫자를 계산·추측하지 않는다.
- `total_rows_count` 가 `grid_data` 행 수보다 많으면 받은 행을 전체처럼 말하지 않고 전체 건수를 밝힌다.
- 통화별 결과는 통화를 함께 쓰고 합쳐 말하지 않는다.
- SQL 문과 접속 정보는 쓰지 않는다(SQL 은 화면 표에 함께 나온다).
- 조회가 실패해도 `submit_sql` 을 한 뒤, 실패한 단계와 확인된 내용만 쓴다. 확인 못 한 것은 「확인하지 못함」.

## 문서만으로 답할 때 (DB 값이 필요 없는 질문)

읽은 문서 내용만으로 답하고 문서에 없는 내용은 덧붙이지 않는다. 목차에 없는 테이블·설명도 덧붙이지 않는다.

- 테이블 목록: OWNER 와 분류(또는 도메인)마다 소제목, 「테이블명 | 테이블 설명」 두 열 표.
- 컬럼·조인 구조: 컬럼 표(컬럼 | 한글명 | 타입 | 키 | 비고), 조인 표(상대 테이블 | 조건 | 카디널리티 | usable). PII 표시는 그대로 밝힌다.
- 근거: 읽은 문서 경로를 한 줄로 적는다. 도메인 정보 문서와 OKF 문서의 표현이 다르면 끝에 「가정」 한 줄로 밝힌다.
