# 결과 판정과 점검

시나리오 탐색은 1절의 오류 처리만 쓴다. 0행이나 결과가 너무 많을 때는 `skills/sql-query/SKILL.md` 의 시나리오 SQL 쓰는 법을 따른다.

## 1. 판정 (`execute_sql` 결과, 위에서부터 맞는 첫 행)

| 결과 | 처리 |
|---|---|
| ORA-00904 잘못된 식별자 | 컬럼명·alias 를 `# Schema` 와 문자 단위로 대조. 공백·특수문자 컬럼은 큰따옴표. 고쳐도 같은 오류면 「컬럼 없음」이라 하지 않고 「접속 DB 조회 실패(ORA-00904)」로 확인 필요에 적는다 |
| ORA-00942 테이블 없음 | `query_name` 의 OWNER·이름 표기 대조 |
| ORA-01031 권한 없음 | `access:select-partial` 의 `접근불가` 컬럼 제거 |
| ORA-01722 숫자 변환, ORA-01841·01843·01861 날짜 | `TO_NUMBER(… DEFAULT NULL ON CONVERSION ERROR)`, 문자열 날짜는 문서 형식대로 문자열 비교 |
| 그 밖의 문법 오류(00907, 00933, 00936, 00979 등) | 괄호·콤마·따옴표·키워드·GROUP BY 누락 |
| 시간 초과, ORA-01013 | 같은 SQL 반복 금지. 의미를 바꾸지 않는 범위에서 기간·법인 조건을 좁히고 불필요한 조인·중간 집계를 뺀다. 그래도 실패하면 `SAMPLE` 이나 COUNT 로 1회만 |
| 0행 | 단정하지 않는다. ① 조건 오타·값 형식(날짜 형식, 코드 vs 라벨) ② soft-delete 플래그 방향(`Y/N` vs `0/1`)·유효기간 ③ VPD·권한 ④ 실제로 없음 순서로 확인. 고칠 근거가 없으면 0행을 정상 결과로 제출 |
| `execute_sql` 이 10행만 돌려줌 | 받은 행은 일부다. 건수·합계는 `COUNT`·`SUM` 으로, 제출한 목록은 `total_rows_count` 로 |
| 행 수가 `row_count` 대비 비정상적으로 적음, 값이 `********` | VPD·마스킹 가능성 → 「확인 필요」 |
| 도구 실패(결과 없이 실패, 연결 실패) | 1회만 다시. 또 실패하면 가장 나은 SQL 로 `submit_sql` |
| 정상 | 2절 점검 |

## 2. 결과 점검 (제출 전)

- 열이 질문이 요구한 값과 맞다(건수는 COUNT, 금액은 금액 컬럼)
- 사용한 테이블·컬럼이 읽은 문서에 있다
- 기간·통화·기준 시점이 질문과 같고, 다른 통화를 합치지 않았다
- 조인으로 합계·건수가 부풀지 않았다(조인 문서 `cardinality`·`fanout`, 테이블 그레인, `near_key` 중복)
- 최댓값·최솟값에서 동점 행이 더 있는지 봤다
- soft-delete·유효기간·플레이스홀더를 반영했다
- 단위가 맞다(수량 vs 건수, 단가 vs 금액)

어긋나면 SQL 을 고친다(상한 안에서).
