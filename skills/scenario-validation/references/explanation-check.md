# 소명 확인

시나리오 SQL 에 걸린 행이 정상으로 설명되는지 소명 경로를 하나씩 확인한다. 걸린 행 하나라도 소명되지 않고 남아야 감사 시나리오가 될 수 있다.

## 1. 준비

한 응답에서 함께 읽는다.

- 원본 SQL 이 읽는 테이블의 문서(`okf/schemas/<OWNER>/tables/<테이블>.md`). `# Schema` 에서 SQL 에 쓰지 않은 컬럼(상태·구분·사유·비고·등록자·등록 시각 등)과 `# Joins` 의 연결된 테이블을 표시해 둔다.
- `okf/wiki/normal-patterns.md`
- 업무 규칙·도메인 정보가 필요하면 AGENTS.md 「업무 규칙 참고」, 「도메인 정보 참고」대로 읽는다.

원본 SQL 실행 결과의 표본으로 걸린 행이 어떤 모양인지 본다.

## 2. 소명 경로

아래 순서로 확인한다. 앞 경로에서 걸린 행이 모두 소명되면 거기서 멈춘다.

| 경로 | 소명되는 경우 | 확인하는 법 |
|---|---|---|
| 조회 착시 | 조인으로 행이 부풂, NULL 비교, 날짜와 시각을 섞어 비교, 삭제 표시 행·유효기간 이력 행이 섞임 | 키별 행 수, 조인 전후 건수, 삭제·이력 조건을 넣었을 때 건수 |
| 적재·데이터 품질 | 배치 일괄 등록(등록 계정 하나, 같은 시각에 몰림), 빈 값·임시값, 시스템 전환·이관 시점의 행 | 등록 계정·등록 시각 분포, 빈 값 비율, `okf/wiki/normal-patterns.md` 「데이터 특성」 |
| 같은 테이블의 다른 컬럼 | SQL 에 쓰지 않은 상태·구분·사유 컬럼 값이 정상 처리를 뜻함 | 걸린 행과 안 걸린 행의 값 분포 비교. 걸린 행에 몰린 값의 뜻 확인 |
| 같은 테이블의 다른 행 | 같은 키의 취소·정정·상계(음수) 행, 분할 행이 있어 합치면 맞음 | 같은 키로 묶어 합계·건수 |
| 코드값 뜻 | 걸린 행의 코드값이 취소·테스트·내부 처리 같은 정상 처리를 뜻함 | 컬럼 코멘트, 공통코드(`skills/scenario-validation/references/bundle-check.md` 「코드값 의미 확인」) |
| 연결된 테이블 | 짝 기록, 후속 처리(취소·반품·정정), 승인·결재 기록이 있음 | 조인 문서가 있는 연결. 없으면 `skills/sql-query/references/joins.md` 「문서 없는 조인」 기준을 지킨 연결. `EXISTS` 로 센다 |
| 대상의 속성 | 거래처·사람·법인이 관계사, 시스템·테스트 계정, 특수 거래처 | 마스터 테이블의 구분 컬럼 |
| 기간 경계 | 짝 기록이나 후속 처리가 분석 기간 밖(직전·직후 달)에 있음 | 확인 질의에서만 기간을 앞뒤로 늘려 찾는다 |
| 단위·환산 | 통화·환율, 부가세 포함 여부, 수량 단위, 반올림 때문에 다름 | 차이 크기 분포, 통화·단위 컬럼 |
| 정상 업무 | `okf/wiki/normal-patterns.md` 「업무 패턴」에 해당 | 문서의 조건을 걸어 센다 |
| 업무 규칙·운영 지식 | `okf/glossary/biz-rules/` 의 예외 규정이나 `domain_knowledge/` 의 운영 노하우로 허용됨 | 문서의 조건을 걸어 센다 |

- 질의 하나로 여러 경로를 함께 봐도 된다(예: 쓰지 않은 컬럼 여러 개를 한 `GROUP BY` 로).
- 문서로 해당 없음이 분명한 경로는 질의하지 않고 이유만 적는다.
- 원본 SQL 결과에 걸린 행을 다시 찾을 키가 없어 확인할 수 없으면 「확인 불가」로 적는다.
- 결재 문서·계약서처럼 DB 밖 증빙으로만 소명될 수 있는 것은 확인하지 못한다. 「감사인이 확인할 소명 자료」로 적는다.

## 3. 소명 조건과 남은 행

남은 행을 세는 질의 1회는 소명 질의 상한(AGENTS.md) 안에서 마지막에 쓸 수 있게 남겨 둔다.

1. 경로에서 행을 설명한 조건을 소명 조건으로 정한다. 업무 말 한 줄과 SQL 조건을 함께 적는다.
2. 소명 조건마다 걸린 행 중 몇 행이 해당하는지 센다.
3. 모든 소명 조건을 뺀 남은 행을 센다. 조건끼리 겹칠 수 있으므로 더하지 않고 한 질의로 센다.

```sql
SELECT COUNT(*) AS REMAINING FROM (<원본 SQL>) s WHERE NOT (<소명 조건 1>) AND NOT EXISTS (SELECT 1 FROM <연결 테이블> t WHERE t.<키> = s.<키> AND <소명 조건 2>)
```

## 4. 기록

경로마다 한 행을 남긴다. 빠진 경로가 없어야 한다.

| 경로 | 확인한 것 | 소명된 행 수 | 결과 | 근거 |
|---|---|---|---|---|
| <경로 이름> | <질의 요지 또는 읽은 문서> | <N>행 \| - | 소명 / 일부 소명 / 해당 없음 / 확인 불가 / 보지 않음(모두 소명됨) / 보지 못함 | <수치 또는 문서 내용> |

- 「확인 불가」와 「보지 못함」은 판정을 막지 않는다. 출력의 「확인 필요」에 올린다.
