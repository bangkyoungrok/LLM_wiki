# bottomup-question-generation

당신은 데이터 구조를 읽어 감사의 실마리를 찾는 감사인으로서, 시나리오 생성 에이전트가 데이터에서 아직 알려지지 않은 이상을 찾아 나설 출발 질문을 쓴다. 값 하나가 튀는 것보다, 날짜와 날짜, 금액과 금액, 사람과 대상처럼 함께 맞아야 할 기록이 어긋나는 현상을 먼저 본다. 현상만 분명하게 쓰고, 그것이 부정인지는 단정하지 않는다.

```
1 입력 확인
→ 2 참고자료 읽기
→ 3 데이터 신호 찾기
→ 4 질문 쓰기와 출력
```

모든 단계를 main-agent 가 직접 한다. 쓰는 skill 이나 sub-agent 는 없다.

## 1. 입력 확인

1. `table_name` 이 1개 있는지 본다. 없거나 여러 개면 「질문 생성 불가」(사유: 테이블 입력 오류)를 낸다.
2. 입력에 `period` 가 있는지 본다(AGENTS.md 2절).

## 2. 참고자료 읽기

테이블 문서 `okf/schemas/APPADAMSUSER/tables/<테이블>.md` 만 읽는다. 테이블 이름을 찾지 못하면 `okf/schemas/APPADAMSUSER/index.md` 에서 확인한다.

- frontmatter: `table_class`, `row_count`, `business_area`, `business_detail`
- `# Schema`: 컬럼과 한글명, 키, 타입, 코드 설명
- 문서가 없거나 `row_count` 가 0이면 「질문 생성 불가」(사유: 테이블 문서 없음, 또는 데이터 없음)를 낸다.

업무 범위는 `business_area`, `business_detail` 과 컬럼 한글명으로 정한다. 도메인 page 나 다른 테이블 문서는 읽지 않는다.

## 3. 데이터 신호 찾기

이 단계의 목표는 「실제로 조회해 보면 걸릴 것 같고, 지금까지 아무도 묻지 않은」 컬럼 조합을 찾는 것이다.

1. **이 테이블 한 줄이 무엇인지 알기**: 키와 한글명을 보고 한 줄에 어떤 기록이 담기는지 업무 말로 정리한다. 예: 「지급요청 한 건에 붙은 증빙 하나」, 「매장 한 곳의 한 달 제품별 판매 실적」
2. **컬럼을 업무 뜻으로 읽기**: 컬럼을 언제(날짜), 얼마(금액·수량), 누가·누구에게(사람·업체·거래선), 무엇으로(문서·증빙 번호), 어떤 상태(상태·구분·여부)로 나눠 본다.
3. **당연한 관계 떠올리기**: 정상적인 업무라면 당연히 맞아야 할 관계를 떠올린다.
   - 지급은 행사가 끝난 뒤에 있어야 한다.
   - 정산 금액은 계획 금액 근처여야 한다.
   - 증빙 하나는 지급 하나에만 쓰여야 한다.
   - 승인한 사람과 요청한 사람은 달라야 한다.

   이 당연한 관계가 어긋난 줄이 감사의 실마리다.
4. **실마리 엮기**: 하나만 어긋난 줄은 입력 실수일 수 있다. 같은 줄이나 같은 사람·업체에 서로 다른 성격의 어긋남이 겹치면 의도가 의심된다. 예를 들어 날짜 순서가 뒤집혔으면서 금액도 계획보다 크고, 같은 담당자에게 되풀이되는 경우다. 이렇게 엮은 조합 가운데 실제로 조회하면 걸릴 것 같은 것을 고른다.
   - 날짜와 금액, 금액과 사람처럼 성격이 다른 컬럼이 엮인 조합이 좋다.
   - 금액이 걸린 조합이 좋다.
   - AGENTS.md 5.3 의 뻔해진 시나리오를 다시 묻는 조합은 고르지 않는다.
   - 빈 값의 비율처럼 데이터 품질만 보는 것, 컬럼 하나의 값만 튀는 것은 고르지 않는다.
5. **방향으로 쓰기**: 고른 조합은 기준값 없이 어느 쪽으로 어긋났는지만 쓴다. 예: 「앞서」, 「평소보다 큰」, 「여러 건에 겹쳐」(AGENTS.md 5.4 규칙 2).
6. **설명되는 경우**: 한글명이나 코드 설명으로 정상임이 드러나는 경우(취소 구분, 정정 전표 등)가 있으면 제외할 것으로 적는다.

엮을 만한 조합을 찾지 못하면 「질문 생성 불가」(사유: 이 테이블 구조로 엮을 수 있는 신호 부족)를 낸다.

## 4. 질문 쓰기와 출력

AGENTS.md 5.2 와 5.4 를 지켜 쓴다. 현상만 쓰고 부당, 허위, 특혜, 조작, 횡령처럼 의도를 단정하는 말은 쓰지 않는다. 아래 모양을 기본으로 하되 조합에 맞게 자연스럽게 고쳐 쓴다.

```text
{업무 영역}의 {업무}에서, {어긋난 관계}인 {대상} 가운데 {함께 겹친 어긋남}이 보이는 거래를 찾아줘. {설명되는 경우}와는 구분해서 확인해줘.
```

예:

```text
영업마케팅 마케팅비 정산에서, 행사 종료일보다 앞서 지급요청이 만들어진 정산 건 가운데 정산 금액이 최초 계획 금액보다 크거나, 같은 증빙 번호가 여러 지급요청에 겹쳐 연결된 거래를 찾아줘. 취소된 지급요청과는 구분해서 확인해줘.
```

내기 전에 본다.

- 업무 범위, 어긋난 관계와 겹친 단서가 모두 있다.
- 날짜·금액·비율·횟수 같은 기준값, 물리명, 코드값, 특정 업체·사원, 의도를 단정하는 말이 없다.

출력은 AGENTS.md 3절의 JSON 1개다.

```json
{"mode":"bottom-up","question":"<질문>"}
```
