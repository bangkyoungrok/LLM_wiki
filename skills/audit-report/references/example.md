# 보고서 예 (줄여 쓴 Top-down 예)

한 시나리오의 보고서를 줄여 쓴 예다. 절 이름·순서, 물리명이 오는 자리, 업무 말로 쓰는 자리를 본다. 내용은 형식을 보이기 위한 것이며 실제 수치·패턴 번호가 아니다. Bottom-up 은 audit-report 「모드별 값」의 Bottom-up 열대로 바꾼다.

````text
# [Top-down][부정 위험] 거래선 마스터에 없는 거래선으로 청구된 빌링

- 범위: 영업
- 분석 기간: 2025-10-01 ~ 2026-09-30 (기본값, 직전 달 말일까지 12개월)
- 작성일: 2026-10-20
- 결과: 152건

## 참고한 근거

> 이 보고서가 무엇을 근거로 만들어졌는지 보여 준다. 실제로 쓰고 읽은 것만 적는다.

- 출발점: 가공 거래처 청구(P-0XX)
- 가설: 2025-10-01 ~ 2026-09-30 영업 빌링 중, 거래선 코드가 비어 있거나 거래선 마스터에 없는 청구는 어느 거래선에 몇 건, 얼마나 있는가?
- 사용 테이블: 판매주문내역 빌링(`APPADAMSUSER.TI_GRPB004B`), 거래선정보(`APPADAMSUSER.TI_GRPB810`), 회사코드(`APPADAMSUSER.TI_GRPF900`)
- 참고 문서: `domain_knowledge/business_document/<영업 문서>.md`, `okf/domains/<영업>.md`, `okf/wiki/patterns/fraud/P-0XX.md`, `okf/wiki/normal-patterns.md`

## 1. 요약

### 1.1 무엇이 문제인가
빌링(청구)은 **항상 등록된 거래선**에 대해 이뤄져야 한다. 거래선 코드가 비어 있거나, 코드는 있으나 거래선 마스터에 없는 청구 건은 **거래선 검증을 거치지 않고 청구가 만들어졌을 가능성**을 본다. 가공 거래처를 이용한 허위 청구 수법을 이 업무에 대입한 것으로, 마스터에 없는 거래선과 청구가 함께 나타나면 정상적인 등록 절차를 건너뛴 흔적일 수 있다. 실행 결과 **152건**이 여기에 해당하며, 그중 가장 두드러진 것은 거래선 A 28건(합계 412,000,000원)·거래선 B 11건(합계 187,000,000원)으로, 미등록 거래선을 이용해 청구했을 가능성을 본다.

### 1.2 문제가 발견된 포인트
- 판매주문내역 빌링(`TI_GRPB004B`): 빌링번호(`BILL_NO`), 거래선코드(`SOLD_TO`), 금액(`LAMT`), 빌링일자(`BILL_DT`), 법인코드(`CMCD`)
- 거래선정보(`TI_GRPB810`): 법인코드(`CMCD`) + 거래선코드(`ENTP_CD`)
- 청구 행의 거래선 코드가 비어 있거나 거래선 마스터에 없으면 의심 건으로 추출

## 2. 발견 경로: 빌링 → 거래선 마스터 조인 분석

### 2.1 1단계: 판매주문내역 빌링 (APPADAMSUSER.TI_GRPB004B)
- 탐지 기원: 분석 기간의 빌링일자(`BILL_DT`) 행

### 2.2 2단계: 거래선정보 (APPADAMSUSER.TI_GRPB810) — 반조인
- 조인 키: `CMCD + SOLD_TO = CMCD + ENTP_CD`
- 마스터에 짝이 없으면 고아 청구로 판정

## 3. 발견 상세

### 3.1 발견 조합·건수 (152건)
- **L1**: 거래선 코드가 비어 있는 청구 — `SOLD_TO IS NULL`
- **L2**: 코드는 있으나 마스터에 없는 청구 — 거래선정보에 `CMCD + ENTP_CD` 매칭 없음
- **L3**: 월별·법인별 집중 — 특정 월·법인에 몰리면 적재 결함 시점 특정 (인터뷰 대상, 맥락 조건)
- 부정 패턴 조합: 가공 거래처 청구(P-0XX), 근거: COSO CA-03-01 승인 통제
- 감사 위험: 등록되지 않은 거래선으로 청구를 만들어 매출을 부풀렸을 위험, 근거: ACFE 허위 청구
- 위험 구분: 부정(고의) — 의심 표시이며 고의를 확인한 것은 아니다

### 3.2 금액 규모
- 건별 청구금액 `LAMT`(지역통화). KRW 합계가 필요하면 환율 환산 별도

## 4. 다각도 검증 (탐지 로직)

### 4.1 L1: 거래선 코드 공백 (핵심 신호)
- `b.SOLD_TO IS NULL`

### 4.2 L2: 고아 코드
- `b.SOLD_TO IS NOT NULL AND c.ENTP_CD IS NULL`
- 미등록 거래선 사용 또는 코드 체계 불일치

### 4.3 L3: 월별·법인 집중
- 월·법인 단위 건수와 금액 합
- 특정 월에 몰리면 프로세스 결함 패턴

### 4.4 제외 조건
- 분석 기간 밖 행 제외. 신용(마이너스) 빌링 제외는 코드값 실측 전 미적용

## 5. 핵심 발견 (예상)

### 5.1 거래선 코드 없는 청구 (핵심 신호 1)
- 청구 생성 시 거래선 검증이 없거나 인터페이스에서 코드가 전달되지 않았을 가능성

### 5.2 마스터에 없는 코드로 청구 (핵심 신호 2)
- 미등록 거래선 사용 또는 시스템 간 코드 체계 불일치

### 5.3 특정 월·법인 집중 (핵심 신호 3)
- 적재 결함 시점 또는 특정 조직의 프로세스 우회

## 6. 시스템 생성 주체 분석

### 6.1 빌링 생성 주체 — TI_GRPB004B.SGID
### 6.2 거래선 마스터 적재 — TI_GRPB810.IF_DT (인터페이스 적재)

## 7. 원인 분석

### 7.1 메커니즘 (추정)
- 수작업 청구 시 거래선 검증 우회, 인터페이스 결함, 마스터 등록 전 선청구
- 위양성: 마스터 적재 시점이 청구보다 늦은 경우

### 7.2 근거
- `TI_GRPB004B`: 「판매주문내역(빌링)」 — 빌링번호·거래선코드·금액·빌링일자(VARCHAR2(8))
- `TI_GRPB810`: 「거래선정보」 — PK `CMCD`, `ENTP_CD`
- 조인 근거: 조인 문서 없음(추측 조인) — 10.1 에 확인 요청
- 부정 수법: 실재하지 않거나 등록되지 않은 거래처 이름으로 청구를 만든다. 청구와 거래처 마스터의 연결이 끊긴 건을 찾아 탐지한다

## 8. 리스크 평가 및 개선 권고

### 8.1 평가 기준
- 그룹(공백/고아)별 건수·금액, 특정 거래선·법인 집중도. ACFE 허위 청구, COSO CA-03-01 승인 통제

### 8.2 영향 분석

### 8.3 개선 권고
- 청구 생성 시 거래선 마스터 존재 검증 강제, 고아 코드 모니터링
````
