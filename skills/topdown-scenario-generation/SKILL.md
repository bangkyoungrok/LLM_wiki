# topdown-scenario-generation

당신은 알려진 부정 수법에서 출발해, 업무 데이터에서 실제로 확인되는 새로운 감사 시나리오를 찾아내는 감사 분석가다. 부정 패턴을 기계적으로 조합하거나 조건 하나로 거르는 데서 멈추지 않고, 이 업무의 흐름과 권한 구조에서 누가 어떤 통제를 우회해 사고를 낼 수 있는지 파고든다. 여러 단계·문서·테이블에 걸쳐 드러나는 수법을 우선하고, 데이터로 확인되지 않거나 기존 시나리오와 조건만 다른 것은 시나리오로 내지 않는다.
결과는 `skills/audit-report/SKILL.md` 형식의 감사 보고서다.

```
1 질문 이해 (main-agent)
→ 2 가설 생성 (topdown-hypothesizer)
→ 3 시나리오 탐색 (main-agent)
→ 4 보고서 (audit-report)
```

각 단계는 앞 단계의 결과를 그대로 이어받는다. 앞 단계를 다시 검증하지 않는다.

## 1. 질문 이해

1. **분석 기간**: 날짜를 말했으면 그 기간, 길이만 말했으면 직전 달 말일까지 그 길이, 말하지 않았으면 직전 달 말일까지 12개월이다(예: 2026-11-17 이면 2025-11-01 ~ 2026-10-31). 이 기간은 끝까지 바꾸지 않는다.
2. **도메인**: `okf/domains/index.md` 에서 질문에 맞는 도메인을 정하고 도메인 page 를 읽는다. 질문에 범위가 없으면 전체다.
3. **테이블**: 도메인 page 「테이블 목록」에서 질문과 관련 있는 테이블을 고른다. 몇 개를 고를지는 질문에 맞춰 판단한다. 업무 표현이 많거나 도메인 page 로 테이블을 찾지 못하면 `schema-linker` 에 맡긴다.
4. **부정 패턴**: `okf/wiki/patterns/fraud/index.md` 에서 질문과 관련 있는 부정 패턴(P-001~P-032)을 고른다. 개수는 정해져 있지 않다.
5. **업무 규칙 (필요할 때만, biz-rules)**: 부정 패턴과 질문만으로는 이 업무의 흐름·통제를 알 수 없으면 AGENTS.md 「업무 규칙 참고」대로 `okf/glossary/biz-rules/<도메인>/index.md` 에서 질문·패턴과 맞는 규칙 문서들을 고른다. 도메인 폴더가 없으면 건너뛴다.

## 2. 가설 생성 — `topdown-hypothesizer`

고른 테이블과 부정 패턴으로 가설을 만들도록 `topdown-hypothesizer` 에 맡긴다. 이 단계는 SQL 을 쓰지 않고 데이터에 던질 자연어 가설 1개를 받는 것이다. 질문, 분석 기간, 도메인, 테이블, 부정 패턴을 넘긴다(형식은 `sub-agents/topdown-hypothesizer/SKILL.md` 의 「입력」). 1단계에서 규칙 문서를 골랐으면 그것도 고른 이유와 함께 넘긴다.

- 가설이 돌아오면 3단계로 간다.
- 「가설 없음」으로 돌아오면 「유효한 시나리오 없음」으로 4단계에 간다.

## 3. 시나리오 탐색

가설을 시나리오 SQL 로 바꿔 실행하고, 쓸 만한 시나리오가 나올 때까지 고친다. main-agent 가 직접 한다.

1. **읽기**(한 응답에서 함께): `skills/sql-query/SKILL.md`, 가설에 나온 테이블의 문서.
2. **컬럼·코드값 확인**: 가설의 조건에 쓸 컬럼·코드값 뜻을 확인할 것이 여럿이면 `term-grounding` 에 맡긴다.
3. **시나리오 SQL 쓰고 확인**: `skills/sql-query/SKILL.md` 에 적힌 시나리오 SQL 쓰는 법대로 쓰고, 건수를 확인하고, 걸린 건을 살펴본다.
4. **다시 하기**: 확정하지 못하면 조건을 바꾸거나 다른 컬럼·조인된 테이블을 써서 3부터 다시 한다. 가설의 뜻을 벗어나는 다른 시나리오로 바꾸지는 않는다.

`execute_sql` 상한(AGENTS.md)에 닿을 때까지 확정하지 못하면 「유효한 시나리오 없음」으로 4단계에 간다.

**시나리오 이름**: 무엇을 찾는지 읽자마자 알 수 있게, 줄이지 않고 풀어 쓴 한 문장으로 짓는다.

- 꼴: 「<어떤 행위>로 <어떤 결과>가 된 경우」. 예: 「과도하게 할인한 제품으로 셀아웃 실적을 부풀려 할인액이 법인 사고기준금액을 넘은 경우」
- 「겹침」, 「~인 건」처럼 조건 이름을 이어 붙이지 않는다.
- 숫자 기준(비율·금액·일수 등), 기간, 건수, 테이블·컬럼 이름, 패턴 ID 는 넣지 않는다. 숫자 기준은 보고서 「점검 조건」에 쓴다.
