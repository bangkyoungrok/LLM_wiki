# 원본 분해와 변형 유형

원본 시나리오를 「감사 골격」으로 분해하고, 골격의 어느 요소를 어떻게 바꿔 변형 시나리오를 만드는지 정하는 규칙이다. 변형은 **원본의 감사 포인트(무엇을 왜 점검하는지)를 지키면서 적용 대상과 조건만 바꾸는 일**이다. 새 위험을 고르거나 데이터에서 새 이상을 찾는 일은 하지 않는다.

## 1. 감사 골격 (원본 분해)

원본을 아래 요소로 나눈다. 요소마다 값과 근거(SQL 의 어느 부분, 어느 OKF 문서)를 적는다. 모르는 요소는 「미확인」으로 두고 가정에 적는다.

| 요소 | 뜻 | SQL 에서 찾는 곳 |
|---|---|---|
| 대상 기록 | 점검 대상 1건의 단위(테이블과 업무 키, 그레인) | FROM 의 기준 테이블, SELECT 의 키 컬럼 |
| 연결 | 함께 보는 상대 테이블과 조인 | JOIN, EXISTS, IN 서브쿼리의 테이블과 조인 조건 |
| 모집단 조건 | 기간, 정상 상태, 데이터 정리(soft-delete, 플레이스홀더), 범위(법인·사이트) | WHERE 가운데 예외와 무관한 공통 조건 |
| 예외 조각 | 이상을 거는 조건 하나하나(AND 로 나뉜 단위). 조각마다 「개념」(예: 최저가인데 미선정)과 「SQL 조건」을 함께 적는다 | WHERE 의 나머지 조건, NOT EXISTS(흐름 조각), IN (… GROUP BY … HAVING)(집단 조각) |
| 비교 축 | 조각이 무엇과 비교하는가: 같은 행의 다른 값, 상대 테이블, 동료 집단, 평소 값, 고정 기준 | 조각의 형태 |
| 행위자 차원 | 업체·거래선·담당자·사이트 가운데 조각이 걸리는 단위 | 조각이나 GROUP BY 의 컬럼 |
| 지표 | 금액·수량·비율·일수 컬럼 | SELECT·조각의 수치 컬럼 |
| 기준 날짜 | 기간 조건의 컬럼과 형식 | WHERE 의 날짜 조건 |
| 감사 위험 | `wiki/risk-interpretation.md` 3절로 고른 행(위험, 경영진 주장, 위험 구분) | — |
| 관련 패턴 | 조각마다 데이터 이상징후 패턴(P-1xx) | `wiki/patterns/index.md` 2·3절 |

### 입력 형태별 분해

- **JSON(`scenario_name`, `scenario_sql`)**: SQL 을 위 표대로 나눈다. 테이블·컬럼은 OKF 테이블 문서로 확인하고, 문서에 없으면 「미확인」으로 적는다. SQL 안의 기간 리터럴은 원본의 기간이다(`AGENTS.md` 5절).
- **기존 시나리오 목록의 이름**: `okf/references/scenarios.md`(있을 때)에서 시나리오 이름, 감사 포인트, 참조 테이블을 찾는다. 목록 파일이 없거나 이름이 없으면 자연어 설명으로 다룬다. SQL 전문은 없으므로 **복원**한다: 감사 포인트를 예외 조각(개념)으로 나누고, 참조 테이블의 문서(`# Schema`, `# T2S 힌트`, 그레인)로 컬럼을 정해 모집단 질의와 예외 질의를 쓴다. `okf/t2s/examples/` 에 같은 시나리오의 검증 예제가 있으면 그 SQL 을 원본으로 쓴다(바인드 변수는 리터럴로). 복원한 SQL 은 「복원」으로 표시하고 가정(컬럼 추정, 코드값)을 적는다.
- **자연어 설명**: 설명을 대상 기록·예외 조각(개념)·행위자·지표로 나누고, 표현이 3개 이상이거나 테이블을 바로 찾지 못하면 `term-grounding` 에 맡겨 테이블·컬럼을 확정한 뒤 SQL 을 쓴다. 이것도 「복원」이다.

## 2. 변형 유형

| 유형 | 바꾸는 요소 | 유지하는 요소 | 대상을 찾는 법 | 예 |
|---|---|---|---|---|
| 테이블 이전 | 대상 기록(테이블), 연결, 컬럼 | 예외 조각의 개념, 감사 위험, 행위자 차원의 뜻 | 사용자가 지정한 테이블, 또는 같은 도메인 page(`okf/domains/<도메인>.md`)의 핵심 테이블 가운데 같은 업무 단계의 테이블. 컬럼은 테이블 문서의 한글명과 `okf/glossary/index.md` 로 대응. 연결은 조인 문서로 다시 구성 | 견적(TI_BQMS005_INFA_QT) 최저가 미선정 → 입찰(TI_BQMS004_INFA_BD) 최저가 미선정 |
| 도메인 이전 | 도메인(업무 흐름), 대상 기록, 연결, 컬럼 | 감사 위험, 예외 조각의 개념(단계 이름으로 추상화: 요청·승인·실행·정산·변경) | 대상 도메인 page 의 업무 흐름에서 원본 조각이 걸리는 단계와 같은 역할의 단계·테이블을 찾는다. 같은 역할이 없으면 변형 불가 | 입찰(bid-qt)의 「선정 뒤 단가 변경」 → 마케팅비(mkt-exp)의 「승인 뒤 지급 조건 변경」 |
| 조건 강화 | 예외 조각(더하기), 모집단 조건(좁히기) | 대상 기록, 감사 위험 | 데이터 이상징후 패턴 조합 규칙(`wiki/patterns/index.md` 4절)과 분류 파일의 「자주 묶이는 패턴」에서 **같은 점검 대상에 걸 수 있는** 조각을 더한다. 정상 업무 제외(`wiki/normal-patterns.md`)를 모집단에 더한다 | 최저가 미선정 → 최저가 미선정이면서 선정 업체와 다른 업체의 제출 IP 가 같음 |
| 조건 확장 | 예외 조각(완화·대체), 행위자 차원, 수준(행 ↔ 집단), 기간·범위 | 대상 기록, 감사 위험 | 임계를 통계 경계로 바꾸기(variation-worker 가 통계 도구로 정함), 건 단위 조건을 행위자 단위 비율로 바꾸기(집단→행 꼴), 차원을 바꾸기(업체 → 담당자), 법인·사이트 범위 넓히기 | 「할인율 30% 초과 건」 → 「담당자별 할인율이 동료 대비 범위 밖인 담당자의 건」 |
| 대칭 변형 | 예외 조각의 방향 | 대상 기록, 연결 | 짝 없음의 방향 뒤집기(A 없는 B ↔ B 없는 A), 상한 ↔ 하한, 앞선 ↔ 늦은, 초과 ↔ 미달 | 출고 없는 청구 → 청구 없는 출고 |

- 한 변형에서 바꾸는 축은 **1~2개**다. 세 축 이상 바꾸면 원본과 다른 시나리오이지 변형이 아니다.
- 감사 위험은 원본과 같은 행을 쓴다. 도메인 이전에서 같은 행을 쓸 수 없으면 「대응 행」을 쓰고 가정에 적는다. 위험 해석 행이 없으면 변형 불가다.
- 예외 조각은 하나 이상 원본과 달라야 한다. 원본과 같은 SQL 이 되면 변형이 아니다.
- 숫자(임계, 일수, 비율)와 코드값을 지어내지 않는다. 원본 값, OKF 문서의 값, 통계 도구가 돌려준 경계만 쓴다.
- 대상 테이블·컬럼·조인을 OKF 에서 찾지 못한 조각은 변형 불가(보고서 4절, 이유: <무엇> 을 찾지 못함)다. 목차에는 있으나 테이블 문서 파일이 없으면 「<테이블> 문서 없음」이다.

## 3. 유형 고르기

사용자가 유형을 말하지 않았을 때 요청 문구로 정한다. 둘 이상 맞으면 위에서부터 첫 번째를 고른다.

| 요청 문구 | 유형 |
|---|---|
| 테이블 이름을 지목함(「B 테이블로」, 「~을 기준으로 조회하면」) | 테이블 이전 |
| 다른 도메인·업무를 지목함(「마케팅비 쪽에도」, 「MRO 에서는」) | 도메인 이전 |
| 「더 감사 가치 있게」, 「정교하게」, 「오탐을 줄여」 | 조건 강화 |
| 「넓게」, 「범위를 늘려」, 「담당자 단위로」, 「비율로」 | 조건 확장 |
| 「반대로」, 「거꾸로」, 「역방향」 | 대칭 변형 |
| 그 밖(「변형해줘」만) | 조건 강화 |

- 변형 개수는 사용자가 말한 수, 없으면 **1개**다. 후보는 요청 개수 + 2개까지 설계하고(같은 유형 안에서 축을 달리 하거나 유형을 달리), 데이터 확인을 통과한 것 가운데 선별 점수 순으로 요청 개수만 낸다.

## 4. 변형 후보 기록 형식

후보마다 아래를 적어 5단계 위임 prompt 에 그대로 넣는다.

1) 번호(V1 …)와 제목 초안(`answer-format.md` 3절 규칙)
2) 유형, 바꾼 축
3) 대응표: 요소 | 원본 | 변형 | 근거 문서
4) 변형 모집단 질의와 예외 질의 초안(한 줄, 분석 기간 리터럴)
5) 바꾼 이유(원본의 어떤 한계를 보완하는지, 또는 어떤 대상으로 넓히는지)
6) 감사 위험(원본과 같음 / 대응 행)과 관련 패턴
7) 비교 지표 정의(variation-worker 가 `TARGET_VAL`·`BASE_VAL` 로 계산할 값. 예: 변형 조건을 충족하는 비율 vs 모집단 전체 비율)
8) 통계 경계가 필요한 조각(있으면 관점과 도구 인자, `stat-views.md` 6절)
9) 확인된 사실(`query_name`·유형과 「테이블 선택」 기록 줄, 날짜 형식, 업무 키, 금액, 차원, 데이터 정리 조건, PII, 조인 근거, 정상 조건)
