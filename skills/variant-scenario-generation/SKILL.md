# variant-scenario-generation

기존 시나리오(기준 시나리오) 1건의 감사 포인트를 이어받고 탐지 조건을 바꿔 새 시나리오를 만든다. 결과는 `skills/audit-report/SKILL.md` 형식의 감사 보고서다.

```
1 질문 이해 (main-agent)
→ 2 시나리오 탐색 (main-agent)
→ 3 보고서 (audit-report)
```

각 단계는 앞 단계의 결과를 그대로 이어받는다. 앞 단계를 다시 검증하지 않는다.

## 1. 질문 이해

1. **분석 기간**: 입력의 `scope.period`(시작일·종료일 모두 포함)를 쓴다. 없으면 직전 달 말일까지 12개월이다. 이 기간은 끝까지 바꾸지 않는다.
2. **도메인 정보**(필요할 때만): 질문의 용어나 업무 배경을 OKF 문서만으로 알 수 없으면 AGENTS.md 「도메인 정보 참고」대로 읽는다.
3. **기준 시나리오 문서**: `okf/wiki/scenario/<시나리오 ID>.md` 를 읽는다. 입력에 시나리오 ID 가 없으면 `okf/wiki/scenario/summary.md` 에서 질문에 맞는 시나리오 1건을 고른다. 문서에는 원문 SQL 이 없다. 조건 인벤토리(조건 ID, 단계, 값, 원본 컬럼, 변형 등급), 조건용 파생 컬럼, 단계별 필터, 공식 단계, 제약, SQL 구조 스켈레톤을 본다.
4. **바꿀 조건**: 입력의 `variant.changes`, `variant.kept_conditions`, `variant.joined_tables`, `variant.cautions` 를 문서의 조건 ID·원본 컬럼·단계에 연결한다. 입력 JSON 이 없으면 질문에서 바꿀 조건과 유지할 조건을 정한다.
5. **지킬 것**:
   - 기준 시나리오 문서 「사용 테이블」은 시나리오 SQL 에서 빼지 않는다.
   - 변형 등급이 「정의」인 조건은 빼지 않고, 「구조」인 조건은 값을 바꾸지 않는다.
   - 문서 「제약」과 입력 `variant.cautions` 를 따른다(함께 바꿔야 하는 조건 등).
   - 새로 조인하는 테이블은 그 테이블 문서 `okf/schemas/<OWNER>/tables/<테이블>.md` 로 연결 키를 확인한다.

## 2. 시나리오 탐색

바꾼 조건으로 시나리오 SQL 을 새로 써서 실행하고, 쓸 만한 시나리오가 나올 때까지 고친다. main-agent 가 직접 한다.

1. **읽기**(한 응답에서 함께): `skills/sql-query/SKILL.md`, 기준 시나리오 「사용 테이블」과 새로 조인하는 테이블의 문서, `okf/wiki/normal-patterns.md`.
2. **컬럼·코드값 확인**: 조건에 쓸 컬럼·코드값 뜻을 확인할 것이 여럿이면(테이블 3개 이상, 또는 확인할 코드값 2개 이상) `term-grounding` 에 맡긴다.
3. **시나리오 SQL 쓰고 확인**: 기준 시나리오의 SQL 구조 스켈레톤, 조건 인벤토리, 파생 컬럼을 보고 바꾼 조건을 넣어 새로 쓴다. 기준 시나리오의 어느 단계까지 쓸지는 필요에 따라 정한다. `skills/sql-query/SKILL.md` 에 적힌 시나리오 SQL 쓰는 법대로 쓰고, 건수를 확인하고, 걸린 건을 살펴본다.
   - 방향만 받은 조건(「더 짧게」, 「평소보다 큰」 등)은 데이터를 보고 값을 정한다. 정한 값과 근거를 보고서에 쓴다.
   - 탐지 조건이 기준 시나리오와 같으면 변형이 아니다. 표현만 바꾸고 걸리는 건이 같은 것도 같다.
4. **다시 하기**: 확정하지 못하면 바꾼 조건의 값을 조정하거나 다른 컬럼을 써서 3부터 다시 한다. 입력이 바꾸라고 한 조건과 유지하라고 한 조건은 벗어나지 않는다.

`execute_sql` 상한(AGENTS.md)에 닿을 때까지 확정하지 못하거나, 바꾼 조건이 행이 없는 테이블에 기대거나, 제약을 지킬 수 없으면 「유효한 시나리오 없음」으로 3단계에 간다.

**시나리오 이름**: 무엇을 찾는지 읽자마자 알 수 있게, 줄이지 않고 풀어 쓴 한 문장으로 짓는다. 기준 시나리오와 같은 이름은 쓰지 않는다.

- 꼴: 「<어떤 행위>로 <어떤 결과>가 된 경우」. 예: 「견적 제출 기간을 아주 짧게 잡아 참여하지 않은 업체가 많은 경우」
- 「겹침」, 「~인 건」처럼 조건 이름을 이어 붙이지 않는다.
- 숫자 기준(비율·금액·일수 등), 기간, 건수, 테이블·컬럼 이름, 시나리오 ID, 조건 ID 는 넣지 않는다. 숫자 기준은 보고서 「점검 조건」에 쓴다.
