# topdown-question-generation

당신은 업무 흐름과 권한 구조를 잘 아는 감사인으로서, 시나리오 생성 에이전트가 아직 아무도 보지 않은 부정 위험을 찾아 나설 출발 질문을 쓴다. 알려진 수법 목록에서 고르지 않고, 이 업무에서 누가 무엇을 결정하고 어디서 확인이 빠지는지를 보고 사고가 날 만한 장면을 직접 그린다. 장면과 단서는 분명하게 주되, 정확한 조건은 시나리오 생성 에이전트에게 맡긴다.

```
1 입력 확인
→ 2 참고자료 읽기
→ 3 위험 장면 그리기
→ 4 질문 쓰기와 출력
```

모든 단계를 main-agent 가 직접 한다. 쓰는 skill 이나 sub-agent 는 없다.

## 1. 입력 확인

1. `table_name` 이 1개 있는지 본다. 없거나 여러 개면 「질문 생성 불가」(사유: 테이블 입력 오류)를 낸다.
2. 입력에 `period` 가 있는지 본다(AGENTS.md 2절).

## 2. 참고자료 읽기

1·2는 한 응답에서 함께 읽는다. 3은 필요할 때만 읽는다.

1. **테이블 문서** `okf/schemas/ADAMSUSER/tables/<테이블>.md`
   - frontmatter: `table_class`, `row_count`, `business_area`, `business_detail`, `tags` 의 `domain:<도메인>`
   - `# Schema`: 날짜, 금액·수량, 사람·업체·거래선, 상태·구분, 문서 번호 컬럼과 그 한글명
   - `# Joins`: 이 테이블과 이어지는 테이블. 업무 흐름의 앞뒤를 아는 데 쓴다.
   - 문서가 없거나 `row_count` 가 0이면 「질문 생성 불가」(사유: 테이블 문서 없음, 또는 데이터 없음)를 낸다.
2. **도메인 page**: `tags` 의 `domain:<도메인>` 으로 `okf/domains/<도메인>.md` 를 읽는다. 태그가 없으면 `okf/domains/index.md` 에서 `business_area` 에 맞는 도메인을 찾는다. 업무 흐름의 단계, 이 테이블이 어느 단계에 있는지, 승인·검증·경쟁·한도 같은 통제를 본다.
3. **glossary**(필요할 때만)
   - `okf/glossary/index.md`: 테이블에 나오는 용어가 업무에서 무슨 뜻인지, 이 업무에 어떤 업무 지식이 있는지 확인한다.
   - `okf/glossary/biz-rules/index.md`: 통제가 어디에 있고 어떤 예외가 허용되는지 알아야 할 때, 이 업무의 도메인 폴더(`okf/glossary/biz-rules/<도메인>/`)에서 규칙 문서를 골라 읽는다. 맞는 폴더가 없으면 건너뛴다.

## 3. 위험 장면 그리기

AGENTS.md 5.1 의 순서대로 생각한다.

1. **이 테이블이 하는 일**: 이 테이블에 쌓이는 기록이 업무에서 무엇인지, 그 앞과 뒤에 어떤 단계가 있는지 정리한다. 예: 「업체가 견적 요청에 낸 제출 기록. 앞에는 견적 요청, 뒤에는 업체 선정과 계약이 있다」
2. **사람과 통제**: 이 단계에서 누가 무엇을 정하는지(요청자, 승인자, 담당자, 업체, 거래선), 그것을 막는 통제가 무엇인지를 2에서 읽은 문서로 찾는다.
3. **나쁜 일을 하려는 사람의 입장에서 생각하기**: 그 사람이 무엇을 노리는지, 어느 통제를 어떻게 피할지, 피하면 이 테이블이나 이어지는 테이블에 어떤 흔적이 남을지 그려 본다. 장면은 여러 개 떠올려 서로 견준다.
4. **장면 고르기**: 아래를 모두 만족하는 장면을 고른다.
   - 이 테이블과 이어지는 테이블의 컬럼으로 흔적을 확인할 수 있다.
   - 여러 사실이 함께 맞아떨어질 때 드러나서, 조건 하나로 끝나지 않는다.
   - AGENTS.md 5.3 의 뻔해진 시나리오를 다시 묻는 것이 아니다.
5. **단서 정하기**: 고른 장면이 데이터에 남길 만한 흔적을 살펴볼 단서로 옮긴다. 기준값은 정하지 않고 방향으로만 쓴다(AGENTS.md 5.4 규칙 2).
6. **정상 업무**: 읽은 문서에 이 장면과 비슷하지만 정상인 업무(허용된 예외, 정해진 절차)가 있으면 제외할 것으로 적는다.

흔적을 데이터로 확인할 수 있는 장면을 찾지 못하면 「질문 생성 불가」(사유: 이 테이블로 확인할 수 있는 위험 장면 없음)를 낸다.

## 4. 질문 쓰기와 출력

AGENTS.md 5.2 와 5.4 를 지켜 쓴다. 아래 모양을 기본으로 하되 장면에 맞게 자연스럽게 고쳐 쓴다.

```text
{업무 영역}의 {프로세스}에서, {누가 무엇을 노리고 어떻게 했을 위험}이 의심되는 거래를 찾을 수 있는 부정 위험 시나리오를 만들어줘. {단서 1}거나 {단서 2}인 경우를 살펴보고, {정상 업무}와는 구분해서 확인해줘.
```

예:

```text
영업마케팅 매출의 청구에서, 영업 담당자가 실적 목표를 맞추려고 기간 말에 청구를 앞당겨 만들었다가 다음 기간 초에 되돌렸을 위험이 의심되는 거래를 찾을 수 있는 부정 위험 시나리오를 만들어줘. 기간 말 청구가 같은 법인의 평소보다 크게 몰렸거나, 몰린 청구의 수량이 같은 거래선의 평소 주문 단위와 다르거나, 바로 다음 기간에 같은 거래선의 반품·정정이 이어진 경우를 살펴보고, 계절 수요나 프로모션에 따른 정상적인 기간 말 청구와는 구분해서 확인해줘.
```

내기 전에 본다.

- 업무 범위, 의심되는 행위, 단서가 모두 있다.
- 날짜·금액·비율·횟수 같은 기준값, 물리명, 코드값, 특정 업체·사원이 없다.
- 이미 운영 중인 시나리오를 다시 묻는 질문이 아니다.

출력은 AGENTS.md 3절의 JSON 1개다.

```json
{"mode":"top-down","question":"<질문>"}
```
