# bottom-up 후보 모으기

테이블 구조에서 출발해 bottom-up 질문 후보 3~5개를 문서만으로 모은다. main-agent 가 직접 모을 때와 `question-table-scout` 가 모을 때 모두 이 파일을 따른다.

## 시작 테이블

- `class:transaction` 이고 `row_count > 0` 인 테이블을 고른다. `has:amount` 인 테이블을 먼저 본다.
- 입력에 테이블 이름이 있으면 그 테이블에서 시작한다.
- 테이블 1개, 또는 같은 도메인·프로세스의 테이블 2~3개에서 시작한다.
- 후보 테이블은 `okf/schemas/<OWNER>/index.md` 의 `## transaction` 분류와 도메인 page 의 테이블 목록에서 고른다.
- 도메인 page 에 「번들 밖」이라고 표시된 테이블은 이 번들 문서가 없으므로 후보에서 뺀다.

## 테이블 문서에서 볼 것

- frontmatter: `table_class`, `table_type`, `row_count`, `size`, `tags`
- `# Schema`: 키, 기준 날짜, 금액, 차원(거래처·담당자 등), 필수 컬럼
- `# Joins`: 관련 테이블과 연결 키(있으면)
- `# T2S 힌트`: 업무일자 컬럼, 날짜 저장 형식, 금액 컬럼, 그레인 단서, 주의사항
- 그레인: 업무 키 또는 1행 단위. `quality:no-pk` 이면 문서의 그레인 단서를 본다.

## 넓히기

1. 시작 테이블의 키·기준 날짜·금액·차원 컬럼을 확인한다.
2. 같은 도메인 page 의 관련 테이블로 넓힌다. 예: 매출 빌링(`TI_NERP_SD_D_BILL`) ↔ 출고(`TI_GRPB017`), EO·PR(`TI_GRPF039`) ↔ 정산(`TI_GRPF060`).
3. 테이블이 여러 개면 **`okf/joins/` 에서 검증된 조인만** 쓴다. `okf/joins/index.md` 에 있는 조인 문서(조건·카디널리티·실측 수치)가 있으면 그 연결 키를 쓴다. 「직접 조인 금지」 목록에 있는 쌍은 쓰지 않는다. 「중복 주의」 조인은 조인 패턴(양쪽 GROUP BY 등)을 조건에 반영한다.
4. 테이블 문서의 `# Joins` 에 「조인 후보(미검증)」로만 표시된 연결은 검증 전이므로 쓰지 않는다. 검증된 조인을 찾지 못하면 단일 테이블 후보로 줄이거나 뺀다.
5. 넓힌 길을 「시작 테이블 컬럼 → 관련 테이블 컬럼」로 적는다.

## 위험 연결

- 테이블 컬럼으로 조건을 쓸 수 있는 이상징후 패턴을 `okf/wiki/patterns/anomaly/index.md` 에서 찾는다. 컬럼으로 조건을 쓸 수 없는 패턴은 뺀다.
- 같은 테이블·컬럼을 쓰는 사고 수법을 `okf/real-cases/patterns.md` 에서 찾는다. 이 번들 문서가 비어 있으면 실제 사고 근거를 쓰지 않는다.
- 감사 위험을 `okf/wiki/risk-interpretation.md` 에서 고른다. 맞는 감사 위험이 없으면 그 후보는 뺀다.

## 후보 형식

```text
### B1
- 시작 테이블: <OWNER.TABLE> (<table_class>, <table_type>, row_count <N>, has:amount)
- 관련 테이블: <OWNER.TABLE>, ... (없으면 「없음」)
- 확장 경로: <시작 테이블 컬럼> → <관련 테이블 컬럼> (검증 조인: <okf/joins 문서 경로>. 없으면 단일)
- 단일/복수: 단일 | 복수
- 핵심 컬럼: <기준 날짜>, <금액>, <업무 키>, <차원>
- 이상 신호: <테이블 구조에서 보이는 신호 한 문장>
- 패턴: <P-1xx 이름>
- 실제 사고: <CS-xxx 제목> (문서 비어 있으면 「없음」)
- 감사 위험: <okf/wiki/risk-interpretation.md 의 해당 행>
- 근거 경로: <도메인 page>, <테이블 문서>, <패턴 파일>, <조인 문서>
```

- 물리명은 테이블 문서에서 복사만 한다.
- 확인하지 못한 값은 「미확인」으로 적는다.
